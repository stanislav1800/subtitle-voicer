# CLAUDE.md

Subtitle Voicer — Windows-приложение, которое читает русские субтитры с экрана игры (захват окна → маска текста → OCR) и озвучивает их локальным TTS (Silero). Полное ТЗ: `docs/TZ.md`, устройство кода: `docs/ARCHITECTURE.md`, вид интерфейса: `docs/UI.md`. Перед любой задачей сверяйся с ним; если решение расходится с ТЗ — сначала спроси, потом правь ТЗ.

## Начало и конец сессии
- **В начале каждой сессии** прочитай `docs/STATUS.md`: текущий этап, что готово, отклонения, открытые вопросы. Не переделывай то, что отмечено готовым, без просьбы пользователя.
- **В конце этапа** (и перед долгим перерывом посреди этапа) обнови `docs/STATUS.md`: что сделано, что осталось, какие проверки ждут пользователя.
- Любое решение, которого нет в ТЗ (выбор по замеру, обход ограничения библиотеки, изменённый порог), — запись в `docs/DECISIONS.md`: дата, решение, почему, какие варианты отброшены.

## Как работаем
- Работаем **по этапам** из раздела 10 `docs/TZ.md`. Этап закрыт, только когда выполнены его критерии «Готово, когда». Не забегай вперёд.
- Если в ТЗ что-то не определено — не придумывай, спроси. Не достигается критерий после 3 попыток — остановись, покажи замеры, спроси (правило остановки, раздел 10).
- Проверки, требующие игры, звука или глаз пользователя, делает пользователь: подготовь команду и попроси проверить.
- Небольшие коммиты с понятными сообщениями на русском.
- Новые зависимости — только если они есть в стеке ТЗ (раздел 7) или с объяснением, зачем.
- API сторонних библиотек (silero, silero-stress, rapidocr, windows-capture, pycaw) сверяй с их актуальной документацией, не пиши по памяти.

## Команды
- Установка: `uv sync`
- Тесты: `uv run pytest`
- Линт: `uv run ruff check .` и `uv run ruff format .`
- Правила зависимостей между слоями: `uv run lint-imports`
- Перед коммитом: `ruff check`, `ruff format --check`, `lint-imports`, `pytest` — всё зелёное (то же проверяет CI)
- Проверка стека: `uv run python tools/smoke_stack.py`
- Бенчмарк OCR: `uv run python tools/ocr_bench.py`

## Код
- Python 3.12, пакет `src/subvoicer/`, полные type hints.
- Идентификаторы и docstring — на английском; UI, логи для пользователя и сообщения коммитов — на русском.
- Структура и слои — строго по `docs/ARCHITECTURE.md`. Новые верхнеуровневые пакеты и нарушения правил зависимостей — только после правки этого файла и согласования.
- `pipeline/` — чистые алгоритмы: без потоков, файлов, Windows, Qt и конкретных движков; время только через `Clock`. Тестируется чистым pytest с фейками из `tests/fakes/`.
- Windows-модули (`pywin32`, `comtypes`, `pycaw`, `winrt`, `windows_capture`, `winreg`) — только в `engines/`. Движок — файл в своём семействе + строка в реестре; тяжёлые импорты внутри `load()`.
- Настройки и зависимости передаются через конструктор, без глобальных синглтонов. Данные по умолчанию — в `resources/`, не в коде.
- Бизнес-логика не зависит от Qt. GUI получает события через сигналы.
- Интерфейс — по макетам `docs/design/` и правилам `docs/UI.md`. Цвета только из `ui/theme.py`, не «по месту».
- Стадии конвейера — отдельные потоки, связь через `queue.Queue`. Ни один поток не должен ронять приложение: ловить, логировать, продолжать.
- Конфиги и профили — pydantic v2 модели, данные в `%APPDATA%/SubtitleVoicer/` через `platformdirs`.

## Жёсткие правила
- OCR и TTS — на CPU. GPU не трогать без явного флага в настройках.
- OCR запускается только при изменении **маски** текста, не сырых пикселей.
- Громкость игры после ducking **всегда** восстанавливается (выход, исключение, закрытие игры, следующий запуск после падения).
- Никаких инъекций в процессы игр (DLL, хуки) до позднего этапа 11.
- Модели и сгенерированные данные не коммитить (см. `.gitignore`).
- Реальные тестовые кадры: `tests/fixtures/real/<игра>/имя.png` + `имя.txt` с правильным текстом.
- Любое изменение формата профиля или настроек = новая `schema_version` + миграция + тест (4.11 ТЗ).
