# ТЗ: Subtitle Voicer — автоозвучка игровых субтитров

Версия: 1.0 (сентябрь 2026)
Статус: утверждено, готово к реализации

---

## 1. Цель и рамки

**Цель.** Десктопное приложение для Windows, которое читает русские субтитры с экрана игры и озвучивает их локальным синтезом речи. Нужно для игр без русской озвучки, где читать субтитры неудобно, особенно в динамичных сценах.

**Рамки:**
- Только Windows 10/11 x64.
- Личное использование. Возможно, позже поделюсь с друзьями. Не продаётся.
- Субтитры в играх считаются **уже русскими**. Модуля перевода нет.
- Всё работает локально, без облачных API. Интернет нужен один раз, для скачивания моделей.
- Тяжёлые вычисления (OCR, TTS) работают на **CPU**, чтобы не отнимать ресурсы видеокарты у игры.

**Вне рамок (не делаем):**
- Перевод с других языков.
- Субтитры над головами NPC и субтитры радио (например, в Cyberpunk: отключаются в настройках игры).
- Другие ОС.
- Внедрение в процесс игры в MVP (хуки только на позднем этапе и только для офлайн-игр).

**Тестовые игры:** GTA 5 (субтитры без подложки — сложный случай), Cyberpunk 2077 (есть имя говорящего и настраиваемая подложка — лёгкий случай), плюс старые игры по ходу дела.

**Окружение пользователя:** Ryzen 7 5800X, RTX 3070 8 ГБ, несколько мониторов, игры в режиме «полноэкранное окно» (borderless).

## 2. Термины

| Термин | Значение |
|---|---|
| Профиль | Настройки для конкретной игры, привязанные к её exe |
| Зона | Прямоугольник на окне игры, в котором ищется текст. Координаты в долях окна (0..1) |
| Тип зоны | `dialog` (автоозвучка), `speaker` (имя говорящего), `note` (читается по хоткею) |
| Маска текста | Бинарное изображение зоны, где остался только текст (фон отброшен) |
| Реплика | Стабилизированный текст диалога с (необязательным) именем говорящего |
| Движок TTS | Реализация синтеза речи за общим интерфейсом |

---

## 3. Сценарии использования

1. **Обычная игра.** Приложение сидит в трее. Запускаю игру, приложение по exe находит профиль и начинает работать. Появился субтитр — через ≤0.7 с звучит голос персонажа, игра приглушается, потом громкость плавно возвращается.
2. **Новая игра без профиля.** Приложение замечает игру в фокусе и предлагает создать профиль (уведомление в трее). Я жму хоткей настройки: кадр игры замирает, выделяю зону субтитров мышкой, выбираю тип, сразу вижу маску и распознанный текст, сохраняю.
3. **Записка.** Жму хоткей «прочитать записку». Если у профиля есть зона `note` — читается она. Если нет — кадр замирает, выделяю область, она читается один раз. Пока звучит записка, автоозвучка диалогов на паузе.
4. **Пропустил реплику.** Хоткей «повторить последнюю».
5. **Кривое распознавание.** Хоткей «сохранить кадр»: кадр зоны, маска и результат OCR сохраняются в папку, файл переносится в `tests/fixtures/`.

## 4. Функциональные требования

### 4.1 Источник кадров (capture)
- Захват **окна игры** (не монитора) через `windows-capture` (Windows Graphics Capture). Окно может быть на любом мониторе.
- Fallback: DXGI Desktop Duplication (`windows-capture` DXGI-режим или `dxcam`) для монитора, на котором находится окно, если WGC отдаёт чёрный кадр (эксклюзивный полноэкранный режим старых игр).
- Частота обработки зон по умолчанию 10 Гц (настраивается). Храним только последний кадр, старые выбрасываем.
- Переживает изменение размера окна и потерю окна (игра закрыта → стоп, без падения).

### 4.2 Обработка зоны
Конвейер для каждой активной зоны `dialog`:
1. Вырезка зоны по долям окна.
2. **Построение маски текста** по пресету профиля:
   - `color` — HSV-диапазоны цветов текста (можно несколько: цвет текста, цвет имени);
   - `bright_on_dark` / `dark_on_bright` — порог с учётом тёмной обводки/тени;
   - `adaptive` — адаптивный порог.
3. **Детекция изменений по маске, а не по сырым пикселям.** Фон в катсценах двигается постоянно — сравнение сырых пикселей даст ложные срабатывания каждый кадр. Сравнение: доля отличающихся пикселей маски или perceptual hash маски. OCR запускается только при изменении маски.
4. Пустая маска (текста нет) = событие «зона опустела».

### 4.3 OCR
- Основной движок: `RapidOCR` (onnxruntime, CPU) с моделью **PP-OCRv5 cyrillic mobile** (PP-OCRv6 кириллицу не поддерживает).
- Fallback-движок: Windows.Media.Ocr (WinRT, язык ru-RU).
- На вход подаётся маска или подготовленный кроп (апскейл при мелком тексте).
- При низкой уверенности — до 2 доп. вариантов предобработки (инверсия, адаптивный порог), берётся результат с лучшей уверенностью. Только при изменении маски.
- **Фильтр мусора:** отбрасывать результат, если средняя уверенность < порога (по умолчанию 0.6), доля кириллицы среди букв < 60%, или длина < 3 символов (кроме списка разрешённых коротких слов: «Да», «Нет», «Ой» и т.п.).
- Результат: строки с текстом, уверенностью и bbox (bbox нужен для определения говорящего по цвету/положению).

### 4.4 Стабилизация и дедупликация
- Текст считается готовым, когда **два распознавания подряд совпали** (rapidfuzz ratio ≥ 90) и маска стабильна ≥ 200 мс (настраивается). Это же решает посимвольный вывод текста.
- **Новая реплика** = текст отличается от предыдущей (ratio < 90) **или** между ними зона была пустой (одинаковая реплика, сказанная дважды, озвучивается дважды).
- Субтитр, который дописывается (вторая строка появилась позже): если новый текст начинается с уже озвученного — озвучивается только добавленная часть.

### 4.5 Определение говорящего
Способ задаётся в профиле (`speaker.mode`):
- `prefix` — имя в начале строки, отделено разделителем (по умолчанию регулярка `^([^:]{1,30}):\s*`);
- `zone` — отдельная зона типа `speaker`;
- `color` — имя отличается цветом (отдельный HSV-диапазон в маске, по bbox строк);
- `none` — имени нет.

Если имя не найдено → эвристика пола по тексту (формы прошедшего времени 1-го лица: «я сказала», «я была» → женский) → иначе голос рассказчика профиля.

### 4.6 Голоса персонажей
- Каждому имени — свой голос. Новому имени голос назначается **детерминированно** (хеш имени → голос из списка нужного пола), сохраняется в профиль, меняется вручную в GUI.
- Пол персонажа по имени хранится в профиле; по умолчанию угадывается эвристикой (4.5), можно поправить.
- Голос рассказчика и голоса по умолчанию (М/Ж) задаются в профиле.

### 4.7 Подготовка текста к синтезу
- Удаление имени говорящего из озвучиваемого текста.
- **Словарь произношений профиля:** замены с ударениями (`"Цири" → "Ц+ири"`), регулярки разрешены.
- Числа → словами (`num2words`, ru).
- Латиница: известные слова из словаря, иначе транслитерация; аббревиатуры (2–5 заглавных букв) — по буквам.
- Ударения и омографы: `silero-stress`.
- Очистка: лишние пробелы, мусорные символы OCR, многоточия.

### 4.8 Синтез речи (TTS)
- Общий интерфейс `TtsEngine` (см. 5.3).
- **Основной движок: Silero v5**, модель `v5_cis_base` (29 русских голосов, лицензия MIT) + пакет `silero-stress` (MIT) для ударений. Только CPU. Частота 48 кГц.
- Fallback: SAPI5 (системные голоса Windows).
- Позже, опционально: Qwen3-TTS 0.6B на GPU (выключен по умолчанию).
- Кеш в памяти: последние ~200 синтезированных фраз, ключ = (текст, голос, скорость).

### 4.9 Политика озвучки (планировщик)
- Новая реплика пришла, а старая звучит → **старая обрывается** с затуханием ~100 мс, начинается новая.
- Реплика исчезла с экрана до конца озвучки → **дочитывается**.
- Если реплики идут быстрее, чем успевают звучать → скорость речи автоматически повышается до ×1.3.
- Чтение записки ставит автоозвучку на паузу; после записки автоозвучка продолжается.

### 4.10 Звук
- Воспроизведение через `sounddevice`, выбор устройства вывода в настройках (по умолчанию системное).
- **Ducking** через `pycaw` (ISimpleAudioVolume) для аудиосессий процесса игры: понижение до 40% (настраивается) с плавным переходом ~150 мс, возврат через ~300 мс после конца фразы.
- **Гарантированное восстановление громкости** игры: при штатном выходе, при исключении, при закрытии игры. Громкость сессий Windows сохраняется между перезагрузками — если не восстановить, игра навсегда останется тихой. Исходная громкость запоминается один раз при первом ducking, а не перед каждым.
- Сессии в эксклюзивном режиме не управляются — ducking молча не работает, приложение не падает.

### 4.11 Профили
- Профиль привязан к имени exe игры.
- Автоопределение: процесс окна переднего плана (`psutil` + `pywin32`) → профиль. Нет профиля → уведомление «создать профиль?».
- Зоны хранятся в долях окна, **отдельно для каждого соотношения сторон** (16:9, 21:9 и т.д.) — некоторые игры сдвигают интерфейс при смене соотношения.
- Импорт/экспорт профиля (один JSON-файл).

### 4.12 Горячие клавиши (глобальные, настраиваемые)
| Действие | По умолчанию |
|---|---|
| Пауза / продолжить автоозвучку | Ctrl+Alt+P |
| Повторить последнюю реплику | Ctrl+Alt+R |
| Пропустить текущую | Ctrl+Alt+S |
| Прочитать записку (зона `note` или выделение) | Ctrl+Alt+N |
| Выделить область и прочитать один раз | Ctrl+Alt+A |
| Настроить зоны профиля | Ctrl+Alt+Z |
| Сохранить кадр зоны для отладки | Ctrl+Alt+D |

### 4.13 Интерфейс (PySide6)
- **Трей:** вкл/выкл, текущий профиль, открыть настройки, выход.
- **Окно настроек:** общие (устройство вывода, громкость озвучки, ducking, частота опроса, автозапуск), горячие клавиши, профили (список, импорт/экспорт), голоса персонажей текущего профиля с кнопкой прослушивания.
- **Редактор зон:** замороженный кадр игры поверх экрана, выделение прямоугольников мышкой, выбор типа зоны, настройка маски (пресет, цвета пипеткой), живой предпросмотр маски и распознанного текста.
- **Отладочный оверлей** (отключаемый, по умолчанию выкл): рамки зон и последний распознанный текст поверх игры.
- **История:** последние 50 реплик (говорящий, текст), кнопка «повторить».

### 4.14 Первый запуск и хранение данных
- Все данные в `%APPDATA%/SubtitleVoicer/` (через `platformdirs`):
  - `settings.toml` — общие настройки;
  - `profiles/<exe>.json` — профили;
  - `models/` — модели OCR и TTS;
  - `logs/` — логи с ротацией;
  - `captures/` — кадры из хоткея отладки.
- При первом запуске модели скачиваются автоматически с прогрессом и проверкой SHA-256. Повторно не качаются.
- Автозапуск с Windows — настраиваемый (по умолчанию выкл), через ключ реестра `HKCU\...\Run`.

## 5. Архитектура

### 5.1 Поток данных

```
 [CaptureThread]  windows-capture (WGC) → слот «последний кадр»
        │
        ▼
 [ZoneWorker] 10 Гц: вырезка зоны → маска → изменилась? ── нет → ждём
        │ да
        ▼
     OCR (RapidOCR, onnxruntime отпускает GIL) → фильтр мусора
        │
        ▼
 [Stabilizer] 2 совпадения + стабильная маска → Реплика(текст, строки, bbox)
        │
        ▼
 [SpeakerResolver] префикс / зона / цвет / эвристика → (имя, пол)
        │
        ▼
 [TextPreparer] убрать имя, словарь произношений, числа, латиница, ударения
        │
        ▼
 [SpeechScheduler] политика: оборвать / дочитать / ускорить / пауза для записки
        │
        ▼
 [TtsWorker] Silero (CPU) + кеш  →  [AudioPlayer] sounddevice  ⇄  [Ducker] pycaw
```

- Стадии связаны через `queue.Queue` и события. Каждая стадия — отдельный поток; тяжёлые вызовы (onnxruntime, torch) отпускают GIL.
- GUI (Qt) в главном потоке, получает события через Qt-сигналы. Бизнес-логика от Qt не зависит.
- `GameWatcher` (отдельный поток, 1 Гц) следит за окном переднего плана и переключает профиль.

### 5.2 Модули (пакет `subvoicer`)

| Модуль | Ответственность | Зависит от Windows |
|---|---|---|
| `capture/` | Источники кадров (WGC, DXGI) | да |
| `vision/` | Вырезка зон, маски, детекция изменений | нет |
| `ocr/` | Движки OCR, фильтр мусора | частично (WinRT) |
| `pipeline/` | Stabilizer, SpeakerResolver, конвейер зон | нет |
| `text/` | Нормализация, словарь произношений, эвристика пола | нет |
| `tts/` | Движки TTS, кеш, загрузка моделей | нет (SAPI5 — да) |
| `audio/` | Плеер, Ducker | да |
| `scheduler/` | Политика озвучки | нет |
| `profiles/` | Модели pydantic, хранение, GameWatcher | частично |
| `hotkeys/` | Глобальные хоткеи | да |
| `ui/` | PySide6: трей, настройки, редактор зон, оверлей | да |
| `app.py` | Сборка всего вместе, жизненный цикл, восстановление громкости | — |

**Правило:** модули без Windows-зависимостей должны тестироваться на чистом pytest без запуска игры. Всё Windows-специфичное — за интерфейсами, в тестах подменяется фейками.

### 5.3 Ключевые интерфейсы (черновик)

```python
class FrameSource(Protocol):
    def start(self, hwnd: int) -> None: ...
    def latest(self) -> Frame | None: ...        # BGRA numpy + размер окна + timestamp
    def stop(self) -> None: ...

class OcrEngine(Protocol):
    def recognize(self, image: np.ndarray) -> OcrResult: ...  # строки: text, confidence, bbox

class TtsEngine(Protocol):
    name: str
    def voices(self) -> list[Voice]: ...          # id, пол, отображаемое имя
    def synthesize(self, text: str, voice_id: str, rate: float) -> Audio: ...  # float32 + sample_rate

class Ducker(Protocol):
    def duck(self, pid: int) -> None: ...
    def restore(self, pid: int) -> None: ...
    def restore_all(self) -> None: ...            # вызывается при любом выходе
```

Позже для хуков добавляется абстракция `TextSource`, выдающая реплики напрямую, минуя capture/vision/ocr.

```json

  "exe": "Cyberpunk2077.exe",
```

## 6. Нефункциональные требования

| Требование | Цель |
|---|---|
| Задержка: субтитр появился → голос начался | медиана ≤ 700 мс, 95-й перцентиль ≤ 1.2 с |
| Нагрузка на CPU во время игры | в среднем ≤ 10% (5800X), без запуска OCR при неизменной маске |
| Память | ≤ 1.5 ГБ |
| GPU | не используется по умолчанию |
| Надёжность | падение любого потока не роняет приложение; громкость игры всегда восстанавливается |
| Логи | уровни INFO/DEBUG, ротация, в DEBUG — время каждой стадии конвейера |
| Точность OCR (CER) | синтетика с подложкой ≤ 2%; синтетика без подложки на пёстром фоне ≤ 8%; реальные кадры — отслеживаем, цель уточнить после сбора фикстур |

## 7. Стек

| Задача | Выбор |
|---|---|
| Python | **3.12** (подтвердить установку всего стека на этапе 0) |
| Менеджер пакетов | `uv` |
| Захват | `windows-capture` ≥ 2.0 (fallback `dxcam`) |
| Обработка изображений | `opencv-python-headless` (headless — чтобы Qt из OpenCV не конфликтовал с PySide6), `numpy` |
| OCR | `rapidocr` ≥ 3.5 + `onnxruntime`, модель PP-OCRv5 cyrillic mobile; fallback `winrt-Windows.Media.Ocr` |
| TTS | `silero` (модель `v5_cis_base`) + `silero-stress`, `torch` (CPU-сборка); fallback SAPI5 через `comtypes`/`pywin32` |
| Текст | `rapidfuzz`, `num2words` |
| Аудио | `sounddevice`, `pycaw`, `comtypes` |
| Процессы / окна | `psutil`, `pywin32` |
| Хоткеи | `pynput` |
| GUI | `PySide6` |
| Конфиги | `pydantic` v2, `tomlkit`, `platformdirs` |
| Тесты / линт | `pytest`, `ruff`, `mypy` (мягкий режим) |

Точные API Silero (`v5_cis_base`, `silero-stress`) и RapidOCR (выбор cyrillic-модели) сверять с их актуальными README на соответствующих этапах — не писать по памяти.

## 9. Тестирование

- **Юнит-тесты** на чистую логику: Stabilizer (посимвольный вывод, повтор реплики, дописывание), SpeakerResolver (все режимы), TextPreparer (числа, латиница, словарь), SpeechScheduler (оборвать/дочитать/ускорить/пауза), эвристика пола, модели профиля.
- **Синтетический набор** (`tools/gen_synthetic.py`): русские фразы разной длины × шрифты × цвета текста × тень/обводка × подложка/без × фоны (тёмный, светлый, пёстрый, «неоновый город»). Для каждого файла известен правильный текст.
- **Реальные кадры:** `tests/fixtures/real/<игра>/*.png` + `.txt` с правильным текстом. Пополняются вручную и через хоткей отладки.
- **Бенчмарк OCR** (`tools/ocr_bench.py`): CER, доля отброшенных результатов, время на зону. Запускается вручную, результаты сравниваются между изменениями предобработки.
- **Ручные проверки** Windows-частей (захват, звук, ducking, хоткеи) — чек-листы в критериях этапов.

## 10. Этапы реализации

Каждый этап заканчивается рабочим состоянием и коммитом. Следующий этап не начинается, пока критерии текущего не выполнены.

### Этап 0. Каркас
- `pyproject.toml` (uv), структура пакетов, ruff, pytest, логирование.
- `tools/smoke_stack.py`: импорт всех зависимостей, версии, загрузка моделей OCR/TTS, синтез одной фразы в wav, OCR одной картинки.

**Готово, когда:** `uv sync` на Python 3.12 проходит; `smoke_stack.py` выводит версии и создаёт wav с речью; `uv run pytest` зелёный (хотя бы пустой тест); `ruff check` чистый.

### Этап 1. Синтетика и OCR
- Генератор синтетических субтитров.
- Модуль `vision/` (пресеты масок) и `ocr/` (RapidOCR cyrillic, фильтр мусора, доп. варианты при низкой уверенности).
- Бенчмарк OCR.

**Готово, когда:** генератор создаёт ≥ 300 изображений с правильными ответами; бенчмарк выдаёт CER по категориям; цели CER из раздела 6 на синтетике достигнуты; время OCR одной зоны ≤ 100 мс на CPU.

### Этап 2. Захват и конвейер текста (без звука)
- `capture/` (WGC окна по hwnd, fallback DXGI).
- Детекция изменений по маске, Stabilizer, SpeakerResolver (`prefix`, `none`).
- CLI-режим: указать exe и прямоугольник зоны → реплики печатаются в консоль.

**Готово, когда:** на видео/летсплее в окне (или в игре) реплики печатаются по одной без дублей; при неизменном субтитре OCR не вызывается (видно в DEBUG-логе); посимвольно печатающийся текст выдаётся одной репликой; юнит-тесты Stabilizer и SpeakerResolver зелёные.

### Этап 3. Озвучка
- `tts/` (Silero v5_cis_base + silero-stress, кеш, SAPI5 fallback), `text/` (TextPreparer), `audio/` плеер, `scheduler/`.
- Хоткеи минимум: пауза, повторить, пропустить.

**Готово, когда:** реплики из этапа 2 озвучиваются; медиана задержки ≤ 700 мс (замер по логам); новая реплика обрывает старую с затуханием; исчезнувшая с экрана реплика дочитывается; очередь ускоряет речь до ×1.3; числа и латиница читаются осмысленно; юнит-тесты TextPreparer и SpeechScheduler зелёные.

### Этап 4. Ducking
- `audio/ducker.py` через pycaw, восстановление при любом выходе.

**Готово, когда:** звук игры плавно приглушается и возвращается; после `kill` процесса приложения во время ducking при следующем запуске громкость игры восстанавливается (исходное значение хранится на диске); эксклюзивный режим не вызывает падения.

### Этап 5. Профили и голоса
- pydantic-модели профиля, хранение, GameWatcher, автопереключение.
- Говорящий: режимы `zone`, `color`; эвристика пола; детерминированное назначение голосов; словарь произношений.

**Готово, когда:** смена игры в фокусе переключает профиль; разные персонажи звучат разными стабильными голосами между перезапусками; словарь произношений применяется; профиль экспортируется и импортируется одним файлом.

### Этап 6. Интерфейс
- Трей, окно настроек, редактор зон с живым предпросмотром маски и OCR, история, отладочный оверлей.
- Предложение создать профиль для новой игры.

**Готово, когда:** профиль для новой игры создаётся полностью из GUI, без правки JSON; все настройки из 4.13 доступны в окне; оверлей включается и выключается.

### Этап 7. Записки и отладка
- Хоткеи: прочитать записку, выделить область, сохранить кадр.
- Пауза автоозвучки на время записки.

**Готово, когда:** записка читается из зоны `note` и из произвольного выделения; автоозвучка на это время молчит и потом продолжается; хоткей отладки сохраняет кадр + маску + OCR-результат в `captures/`.

### Этап 8. Удобство
- Автоскачивание моделей при первом запуске с прогрессом и SHA-256.
- Автозапуск с Windows (настраиваемый).

**Готово, когда:** на чистой папке `%APPDATA%` приложение само скачивает модели и работает; галочка автозапуска реально включает/выключает запуск.

### Поздние этапы (по желанию)

- **10.** `HookSource` через `lunahook-py` — только офлайн-игры, с явным запретом для игр с античитом.
- **11.** Сборка `.exe` (Nuitka / PyInstaller) для друзей.
- **12.** Автоопределение зоны субтитров.

## 11. Известные риски

| Риск | Что делаем |
|---|---|
| Субтитры без подложки на ярком фоне (GTA 5) | Маска по цвету + обводке, несколько вариантов предобработки, фильтр мусора |
| Цвет субтитров зависит от настроек игры (режимы для дальтоников в Cyberpunk) | Цвета только из профиля, пипетка в редакторе зон |
| WGC отдаёт чёрный кадр в эксклюзивном полноэкранном режиме | Fallback DXGI; рекомендация играть в borderless |
| Игры с античитом | Только захват экрана; никаких инъекций в MVP |
| Громкость игры осталась пониженной после падения | Исходная громкость на диске + восстановление при следующем запуске |
| Большой размер torch | CPU-сборка torch; позже проверить ONNX-вариант Silero |
| Ударения в выдуманных именах | Словарь произношений профиля |
