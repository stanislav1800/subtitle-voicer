## 1. Цель и рамки

**Цель.** Десктопное приложение для Windows, которое читает русские субтитры и другие тексты с экрана игры и озвучивает их локальным синтезом речи. Нужно для игр без русской озвучки, где читать субтитры неудобно, особенно в динамичных сценах.

**Рамки:**
- Только Windows 10/11 x64. Десктопное приложение (PySide6), не веб.
- Личное использование. Возможно, позже поделюсь с друзьями. Не продаётся.
- Субтитры в играх считаются **уже русскими**. Модуля перевода нет.
- Всё работает локально, без облачных API. Интернет нужен для скачивания моделей и для необязательного импорта персонажей из вики (поздний этап).
- Тяжёлые вычисления (OCR, TTS) работают на **CPU**, чтобы не отнимать ресурсы видеокарты у игры.

**Вне рамок (не делаем):**
- Перевод с других языков.
- Текст, который появляется в разных местах экрана (подсказки у курсора, описание предмета при наведении): зоны фиксированы; для такого текста — «выделить и прочитать» по хоткею.
- Субтитры над головами NPC и субтитры радио (например, в Cyberpunk: отключаются в настройках игры).
- Чтение имён персонажей и текстов из файлов игр.
- Другие ОС.
- Внедрение в процесс игры в MVP (хуки только на позднем этапе и только для офлайн-игр).

**Тестовые игры:** GTA 5 (субтитры без подложки и без имён — сложный случай), Cyberpunk 2077 (есть имя говорящего и настраиваемая подложка — лёгкий случай), плюс старые игры по ходу дела.

**Окружение пользователя:** Ryzen 7 5800X, RTX 3070 8 ГБ, несколько мониторов, игры в режиме «полноэкранное окно» (borderless).

| Персонаж | Запись профиля: основное имя, варианты имени, пол, голос |
| Движок TTS | Реализация синтеза речи за общим интерфейсом |
| Режим разработчика | Настройка, открывающая отладочные инструменты (4.13) |

## 3. Сценарии использования

1. **Обычная игра.** Приложение сидит в трее. Запускаю игру, приложение находит профиль и начинает работать. Появился субтитр — через ≤0.7 с звучит голос персонажа, игра приглушается, потом громкость плавно возвращается.
2. **Новая игра без профиля.** Приложение замечает игру на весь экран и предлагает создать профиль (уведомление). Когда на экране есть субтитр, жму хоткей настройки: кадр игры замирает, выделяю зону мышкой (выбрав шаблон «Диалоги»), пипеткой указываю цвета, сразу вижу маску и распознанный текст, сохраняю.
3. **Настройка без игры.** Открываю профиль в настройках, выбираю «Настроить по скриншоту», указываю полный скриншот игры с субтитром и настраиваю зоны так же, как в игре.
4. **Записка или другой текст на своём месте.** Для игры заведена зона «Записка» с поведением «по хоткею» и клавишей Ctrl+Alt+1. Открыл записку в игре — жму Ctrl+Alt+1, текст читается. Автоозвучка на это время молчит.
5. **Произвольный текст.** Жму Ctrl+Alt+A, выделяю область на замершем кадре, она читается один раз.
6. **Неправильное ударение.** В трее открываю «Последние реплики», выбираю фразу → «Исправить произношение» → нажимаю на слово, пишу, как читать, слушаю, сохраняю. Правка сразу действует во всех формах слова.
7. **Пропустил реплику.** Хоткей «повторить последнюю».
8. **Библиотека (поздний этап).** Приложение само находит игры из Steam, Epic и GOG; остальные добавляю, указав exe. В списке профилей видно, какие игры настроены.

## 4. Функциональные требования

### 4.1 Источник кадров (capture)
- Захват **окна игры** (не монитора) через `windows-capture` (Windows Graphics Capture). Окно может быть на любом мониторе.
- Fallback: DXGI Desktop Duplication (`windows-capture` DXGI-режим или `dxcam`) для монитора, на котором находится окно, если WGC отдаёт чёрный кадр (эксклюзивный полноэкранный режим старых игр). Чёрный кадр = максимум яркости пикселей < 5; переключение на DXGI после 10 чёрных кадров подряд. Кадр монитора **обрезается до прямоугольника клиентской области окна**, чтобы «кадр захвата» имел тот же смысл, что и при WGC.
- Время кадра — `time.monotonic()` в момент получения кадра приложением (используется для замера задержки).
- Частота обработки зон по умолчанию 10 Гц (`poll_hz`). Храним только последний кадр, старые выбрасываем.
- Переживает изменение размера окна и потерю окна (игра закрыта → стоп, без падения).
- **Восстановление захвата.** Если захват перестал отдавать кадры или вернул ошибку (сон и пробуждение ПК, смена разрешения монитора, переключение игры между оконным и полноэкранным режимом, отключение монитора, потеря доступа DXGI) — захват пересоздаётся через 1 с, до 5 попыток подряд; при успехе счётчик сбрасывается. После 5 неудач — уведомление «Не удаётся захватить окно игры» и повтор раз в 10 с, пока жив процесс игры.
- **HDR.** На этапе 2 проверить, в каком формате приходит кадр, когда в Windows/игре включён HDR (8-битный BGRA с тональной компрессией или другой формат). Если цвета отличаются от SDR — определять включённый HDR и показывать в редакторе зон предупреждение «HDR включён: цвета зон настраивайте с включённым HDR и не переключайте его». Результат проверки — в `docs/DECISIONS.md`.
- **DPI.** Процесс приложения при старте объявляет Per-Monitor DPI Awareness v2 (`SetProcessDpiAwarenessContext`). Все координаты внутри приложения — в **физических пикселях кадра захвата**. Доли зон считаются от размеров кадра захвата, а не от логических координат Qt. Редактор зон переводит координаты мыши в физические пиксели кадра.
- **Фокус.** Захват и озвучка продолжаются, пока жив процесс игры с активным профилем, **независимо от того, в фокусе ли её окно** (игра на одном мониторе, мышь на другом — озвучка идёт). Активный профиль меняется, только когда в фокус попадает окно другой игры, у которой есть профиль.

### 4.2 Зоны и их обработка

**Поля зоны** (полный формат — 5.4):
- `id`, `name` (отображаемое имя), `kind` (`text` | `speaker`), `rect`, `mask` (4.2.1);
- только для `text`: `trigger` (`auto` | `hotkey` | `off`), `hotkey` (для `hotkey`), `policy` — **политика озвучки**: `priority` (`high` | `normal` | `low`), `voice` (4.6), `speaker` (способ определения говорящего, 4.5), `repeat_cooldown_min` (4.4), `duck` (приглушать ли игру, 4.10); необязательные переопределения `stabilization` и `ocr`.
- **Политика озвучки — отдельная модель (`VoicingPolicy`), общая для всех источников текста**: зон сейчас и каналов хуков на этапе 11 (4.17). Всё, что после получения текста (говорящий, голос, приоритет, повторы, приглушение), не зависит от того, откуда текст пришёл.
- В раскладке — не больше 12 зон.

**Шаблоны при создании зоны** (заполняют поля, дальше всё можно поменять):

| Шаблон | trigger | priority | voice | speaker | repeat_cooldown_min | duck | mask |
|---|---|---|---|---|---|---|---|
| Диалоги | `auto` | `high` | `speaker` | `prefix` | 0 | да | `bright_on_dark` |
| Записка | `hotkey` | — | `narrator` | `none` | 0 | да | `adaptive` |
| Уведомления | `auto` | `normal` | `narrator` | `none` | 2 | нет | `bright_on_dark` |
| Цель задания | `auto` | `low` | `narrator` | `none` | 10 | нет | `bright_on_dark` |
| Имя говорящего | — (вид `speaker`) | — | — | — | — | — | `color` |

#### 4.2.1 Маска и детекция изменений
Для каждой зоны с `trigger = auto` на каждом цикле `poll_hz`:
1. Вырезка зоны по долям кадра.
2. **Построение маски текста** по пресету:
   - `color` — диапазоны цветов текста в HSV **в формате OpenCV** (H 0–179, S 0–255, V 0–255); можно несколько диапазонов;
   - `bright_on_dark` — светлый текст с тёмной обводкой/тенью: порог по яркости (`threshold`, по умолчанию 200) + морфологическое закрытие;
   - `dark_on_bright` — то же для тёмного текста (`threshold` по умолчанию 60);
   - `adaptive` — `cv2.adaptiveThreshold`.
   После пресета: удаление мелкого шума (связные компоненты площадью < 0.02% зоны).
3. **Детекция изменений по маске, а не по сырым пикселям.** Фон в катсценах двигается постоянно — сравнение сырых пикселей даст ложные срабатывания каждый кадр. Маска считается изменившейся, если доля отличающихся пикселей маски > `change_ratio` (0.5%) площади зоны. OCR запускается только по правилам стабилизации (4.4).
4. Маска пустая, если доля белых пикселей < `empty_ratio` (0.1%) площади зоны → событие «зона опустела».

Зоны с `trigger = hotkey` в цикле не обрабатываются: они читаются разово по своей клавише (4.9). Зоны `off` не обрабатываются вовсе. Зона вида `speaker` обрабатывается только вместе со своей текстовой зоной (4.5).

### 4.3 OCR
- Основной движок: `RapidOCR` (onnxruntime, CPU) с моделью распознавания **PP-OCRv5 mobile** (PP-OCRv6 кириллицу не поддерживает). Кандидаты — `cyrillic` (все кириллические языки) и `eslav` (только русский, украинский, белорусский); модель по умолчанию выбирается по CER на бенчмарке этапа 1, выбор записывается сюда, замеры — в `docs/DECISIONS.md`. **Выбрано по замеру этапа 1: `cyrillic`** (CER с подложкой 0.8% против 0.9% у `eslav`, без подложки на «шуме» и «пёстром» — 1.2% против 1.6%).
- Fallback-движок: Windows.Media.Ocr (WinRT, язык ru-RU). Используется, если RapidOCR не инициализировался, или если в профиле явно задано `"ocr": {"engine": "winrt"}`.
- **Что подаётся на вход OCR** — определяется замером на этапе 1. Бенчмарк сравнивает три варианта: (а) исходный кроп зоны; (б) кроп, где всё вне маски (с расширением маски на 2 px) закрашено чёрным; (в) маска как чёрный текст на белом. Лучший по CER вариант становится входом по умолчанию для каждого пресета; выбор записывается в этот раздел ТЗ, замеры — в `docs/DECISIONS.md`. **Выбрано по замеру этапа 1: вход (а), исходный кроп, — для всех пресетов** (CER 2.4% против ~7% у (б) и (в) на `color`; `color` и `bright_on_dark` измерены, для `dark_on_bright` и `adaptive` светлой синтетики нет, а вход (а) от маски не зависит). Апскейл ×2 (`INTER_CUBIC`), если высота строки текста < 32 px (параметр `ocr.upscale`).
- **Низкая уверенность** = средняя уверенность строк < 0.8. Тогда прогоняются до 2 оставшихся вариантов входа из списка выше, берётся результат с наибольшей средней уверенностью.
- **Фильтр мусора:** отбросить результат, если средняя уверенность < `ocr.min_confidence` (по умолчанию 0.6), или доля кириллицы среди букв < 60%, или длина текста (без пробелов и пунктуации) < 3 символов — кроме разрешённых коротких слов: «да», «нет», «ой», «ах», «эй», «ну», «ага», «угу», «ого», «ха», «ок», «я», «ты», «мы» (сравнение без учёта регистра и пунктуации).
- **Порядок строк:** сверху вниз, в пределах строки слева направо; строки склеиваются через пробел (для зон с `trigger = hotkey` и для выделения — через перевод строки, чтобы сохранить абзацы).
- Результат: строки с текстом, уверенностью и bbox.

### 4.4 Стабилизация и дедупликация (зоны `auto`)
Для каждой зоны с `trigger = auto` — конечный автомат. Параметры: `stable_ms` = 200, `max_wait_ms` = 1500, `match_ratio` = 90 (rapidfuzz `ratio`).

| Состояние | Событие | Действие → новое состояние |
|---|---|---|
| `EMPTY` | маска стала непустой | запомнить время `t_change` → `CHANGING` |
| `CHANGING` | маска изменилась | обновить `t_last_change` → `CHANGING` |
| `CHANGING` | маска не менялась `stable_ms` **или** с `t_change` прошло `max_wait_ms` | **один** запуск OCR → обработка результата → `SHOWN` |
| `CHANGING` / `SHOWN` | маска опустела | `EMPTY`, флаг `was_empty = true` |
| `SHOWN` | маска изменилась | `t_change` = сейчас → `CHANGING` |

- `max_wait_ms` — предохранитель: если маска «дёргается» непрерывно (фон того же цвета, что текст, или очень длинный посимвольный вывод), OCR всё равно запускается.
- **Нормализованный текст** (для всех сравнений в этом разделе): нижний регистр, `ё → е`, без пунктуации, пробелы схлопнуты.
- **Обработка результата OCR** (после фильтра мусора 4.3), `last` — последняя озвученная реплика этой зоны. Автомат выше — только для зон (он про маски); обработка результата ниже — **общий модуль для всех источников текста** (зоны, хуки): он получает текст, канал-источник и флаг `was_empty` и не знает, откуда они.
  0. Такой же текст (`ratio >= match_ratio`) из **другого** источника уже звучал за последние 3 с → ничего. Защита от двойной озвучки, если одни и те же субтитры ловят и зона, и хук.
  1. Результат отброшен фильтром → ничего.
  2. `repeat_cooldown_min > 0` и такой текст (`ratio >= match_ratio`) уже звучал из этой зоны за последние `repeat_cooldown_min` минут → ничего. (Память зоны: нормализованный текст → время последней озвучки.)
  3. `was_empty == true` → **новая реплика** (даже если текст совпадает с `last`: одинаковая фраза, сказанная дважды, озвучивается дважды). Сбросить `was_empty`.
  4. `len(text) > len(last) + 3` и `ratio(text[:len(last)], last) >= match_ratio` → **продолжение**: озвучивается только часть `text` после первых `len(last)` символов, тем же голосом, что и `last` (говорящий не переопределяется) (см. 4.9). После этого `last = text`.
  5. `ratio(text, last) >= match_ratio` → тот же текст, ничего.
  6. Иначе → **новая реплика**.
  - При новой реплике `last = text`. Говорящий определяется по 4.5 только для новой реплики.

### 4.5 Определение говорящего
Способ задаётся **в текстовой зоне** (`speaker.mode`):
- `prefix` — имя в начале первой строки, отделено разделителем (по умолчанию регулярка `^([^:]{1,30}):\s*`);
- `zone` — отдельная зона вида `speaker`, её id указан в `speaker.zone_id`; OCR этой зоны выполняется вместе с OCR текстовой зоны;
- `color` — имя отличается цветом: строится **вторая маска** по `speaker.colors_hsv` в той же зоне, по ней отдельный OCR — его результат и есть кандидат в имя; из маски текста пиксели цвета имени исключаются;
- `none` — имени нет.

**Проверка кандидата в имя** (все условия, иначе имени нет):
- 1–3 слова, длина 2–30 символов, первая буква заглавная, без цифр (иначе «Встретимся в 22:30» даёт «имя» «Встретимся в 22»);
- нормализованный кандидат не входит в **стоп-лист профиля** `speaker_stoplist` (по умолчанию: «совет», «задание», «цель», «внимание», «подсказка», «примечание», «награда», «получено», «новое»; редактируется в настройках профиля).
- Если кандидат отвергнут в режиме `prefix`, префикс **не** вырезается из текста (фраза «Совет: нажмите Q» озвучивается целиком).

**Сопоставление с персонажами профиля:**
1. Нормализованный кандидат совпал с основным именем или вариантом имени персонажа → этот персонаж.
2. Иначе нечёткое сравнение со всеми именами и вариантами: лучший `ratio >= 90` → этот персонаж (защита от ошибок OCR: «Джудн» → «Джуди»).
3. Иначе → новый персонаж (4.6).

**Эвристика пола по тексту** (модуль `pipeline/speaker/gender.py`, регулярки Python `re` с `re.IGNORECASE`, проверяется только текст текущей реплики без имени):
- женский: `\bя\s+(\w+)(ла|лась)\b`, `\b(\w+)(ла|лась)\s+я\b`, `\bя\s+(рада|готова|должна|уверена|согласна|одна|сама|виновата|знакома)\b`;
- мужской: `\bя\s+(\w+)(л|лся)\b`, `\b(\w+)(л|лся)\s+я\b`, `\bя\s+(рад|готов|должен|уверен|согласен|один|сам|виноват|знаком)\b`;
- для мужских шаблонов на `л` совпавшее слово отбрасывается, если оно в списке исключений (существительные на «-л»): стартовый список — пол, стол, зал, мел, вол, угол, посол, орёл, осёл, козёл, футбол, ангел, дятел, пепел, котёл, узел, тыл; список лежит в `resources/gender_exceptions.txt` и дополняется;
- совпали мужские и женские одновременно или ни одного → пол не определён.

### 4.6 Голоса и персонажи

**Голос зоны** (`voice.mode`):
- `speaker` — по говорящему: персонаж → его голос; имени нет → эвристика пола → голос по умолчанию этого пола (`default_voices`); пол не определён → голос рассказчика;
- `fixed` — всегда `voice.id`;
- `narrator` — голос рассказчика профиля.

**Персонаж** (запись в `characters` профиля):
- `name` — основное имя; `aliases` — варианты имени (все считаются одним персонажем);
- `gender` — `male` / `female` / `unknown`; `gender_locked` — пол задан вручную или импортом, автоматика его не меняет;
- `voice` — id голоса или `null` (ещё не назначен); `voice_locked` — голос выбран вручную, автоматика его не меняет;
- `source` — `auto` (появился из субтитров), `import`, `manual`.

**Новый персонаж из субтитров:** `source = auto`, пол — эвристика по тексту реплики (или `unknown`), `gender_locked = false`, `voice = null`.

**Назначение голоса** — в момент **первой озвученной реплики** персонажа, если `voice == null`: из списка голосов его пола (для `unknown` — из всех голосов), отсортированного по id; стартовый индекс `int(sha1(основное имя в нижнем регистре, utf-8).hexdigest(), 16) % n`; если голос уже назначен другому персонажу профиля — следующий по списку (по кругу); если заняты все — стартовый. Так уникальные голоса достаются тем, кого реально встречаешь, а не всему импортированному списку.

**Уточнение пола:** если `gender_locked == false`, `gender == unknown`, и реплика персонажа даёт однозначный пол → пол обновляется; если при этом `voice_locked == false` → голос переназначается по правилу выше.

**Действия в настройках профиля:** изменить пол/голос (ставит соответствующий `*_locked = true`), прослушать, добавить вручную (`source = manual`), удалить, **объединить** (персонаж A становится вариантом имени B: основное имя и варианты A добавляются в `aliases` B, запись A удаляется; голос и пол остаются от B).

**Импорт персонажей из текста** — файл или вставка, UTF-8, разделитель `;`, строка заголовка необязательна:
```
имя;пол;варианты
Джуди Альварес;ж;Джуди
Джонни Сильверхенд;м;Джонни|Сильверхенд
Такэмура;;
```
- пол: `м` / `ж` / пусто (`unknown`); варианты через `|`;
- персонаж ищется по имени и вариантам (правила 4.5): найден → добавить недостающие варианты; пол обновить, только если `gender_locked == false` и в файле пол указан; новый → `source = import`, `gender_locked = true` если пол указан, `voice = null`;
- голоса и `voice_locked` импорт не трогает никогда;
- после импорта — отчёт: добавлено / обновлено / пропущено строк с причиной.

**Голос рассказчика и голоса по умолчанию** задаются в профиле. При создании профиля: `narrator_voice` — первый по id голос с полом `male`, `default_voices.male` — второй мужской (или первый, если он один), `default_voices.female` — первый женский. Если голосов нужного пола нет — первый голос каталога.

**Каталог голосов** — файл `src/subvoicer/resources/voices/silero_v5.toml` (дальше — `voices.toml`): для каждого голоса движка `id`, `gender` (`male` / `female` / `unknown`), отображаемое имя. **Список id берётся из самой модели** (перечень спикеров, который отдаёт загруженная модель Silero), а не из примеров в этом ТЗ. Пол голосов исполнитель определить не может: на этапе 3 он создаёт `tools/voice_samples.py`, который синтезирует по одной фразе каждым голосом в `samples/<id>.wav`, заполняет `voices.toml` со значением `gender = "unknown"`, и **просит пользователя прослушать и проставить пол**. Пока разметки нет, все голоса `unknown` и работают правила выше для `unknown` — это ожидаемо и не ошибка.

### 4.7 Подготовка текста к синтезу
Порядок обработки:
1. Удаление имени говорящего (если оно принято по 4.5).
2. **Словарь произношений профиля** (4.7.1).
3. Числа → словами (`num2words`, `lang="ru"`).
4. Латиница: аббревиатуры (слово из 2–5 заглавных латинских букв) — по названиям английских букв кириллицей («эй», «би», «си», «ди», …, таблица в `resources/letter_names.toml`); остальные латинские слова — побуквенная транслитерация по простой таблице (`a→а, b→б, c→к, ch→ч, sh→ш, …`, таблица в `resources/translit.toml`).
5. Ударения и омографы: `silero-stress`. **Слова, в которых уже стоит `+`** (из словаря), расстановка не трогает. Если `silero-stress` перезаписывает готовые ударения — такие слова перед расстановкой подменяются плейсхолдерами и возвращаются после (проверить поведение библиотеки, не предполагать).
6. Очистка: лишние пробелы, мусорные символы OCR (`|`, `_`, `~`, одиночные символы вне слов), многоточия → пауза.
7. Длинный текст (больше 2 предложений) разбивается на предложения; синтез и воспроизведение идут потоково — первое предложение начинает звучать, пока синтезируются следующие.

#### 4.7.1 Словарь произношений
Запись: `{"from": "...", "to": "...", "regex": false}`. `+` перед гласной в `to` ставит ударение.
- **Обычная запись** — замена целого слова, без учёта регистра, `ё = е`: `NCPD → эн си пи ди`.
- **Запись со звёздочкой** — все формы слова: `from` заканчивается на `*` → совпадает любое слово, начинающееся с этой основы; `to` заканчивается на `*` → на место `*` подставляется окончание найденного слова. `Арасак* → Арас+ак*` превращает «Арасаки» в «Арас+аки», «Арасакой» в «Арас+акой».
- **Регулярное выражение** (`regex: true`) — для продвинутых случаев, применяется как есть.
- Порядок применения: сначала обычные и со звёздочкой (длинные `from` раньше коротких), потом регулярные.
- Действует только в своём профиле.

### 4.8 Синтез речи (TTS)
- Общий интерфейс `TtsEngine` (см. 5.3).
- **Основной движок: Silero v5**, модель `v5_cis_base` (29 русских голосов, лицензия MIT) + пакет `silero-stress` (MIT) для ударений. Только CPU. Частота 48 кГц.
- Fallback: SAPI5 (системные голоса Windows). Используется, если Silero не инициализировался.
- Позже, опционально: Qwen3-TTS 0.6B на GPU (выключен по умолчанию).
- Кеш в памяти: последние `tts_cache_size` (200) синтезированных фраз, ключ = (текст, голос, скорость).

### 4.9 Политика озвучки (планировщик)
Все источники реплик идут в один планировщик. У каждой реплики есть приоритет: приоритет её зоны (`high` / `normal` / `low`) или **ручной** (`manual`) — для всего, что вызвал пользователь: зона по хоткею, «выделить и прочитать», «повторить», прослушивание в настройках.

**Правила:**
- **Ручная** реплика обрывает звучащую (затухание ~100 мс), очищает очередь и ставит автоозвучку на паузу до своего окончания. Реплики зон `auto`, пришедшие в это время, отбрасываются, а не копятся.
- Новая `auto`-реплика с приоритетом **выше** звучащей → обрывает её (затухание ~100 мс) и звучит.
- **Такой же** приоритет → новая обрывает старую (так работают диалоги: следующая фраза важнее недослушанной).
- **Ниже** → встаёт в очередь (по приоритету, затем по времени). Если за 5 с (`low_priority_ttl_s`) не дождалась — отбрасывается.
- **Продолжение** (4.4, п.4) → не прерывает текущую фразу, а встаёт в очередь сразу за ней, вне зависимости от приоритетов.
- Реплика исчезла с экрана до конца озвучки → **дочитывается** (исчезновение текста ничего не прерывает).
- **Автоускорение.** Счётчик `interrupts` — сколько реплик приоритета `high` подряд были оборваны новыми репликами `high`. Скорость следующей реплики: `rate = base_rate × min(1.3, 1 + 0.15 × (interrupts − 1))` при `interrupts ≥ 2`, иначе `base_rate` (×1.15 после двух обрывов подряд, ×1.3 после трёх и более). Как только реплика `high` дозвучала до конца, `interrupts = 0`. Реплики других приоритетов счётчик не меняют.
- **Как меняется скорость:** средствами движка TTS (у Silero v5 — SSML `<prosody rate>`, проверить по документации). Если движок этого не поддерживает — остановиться и спросить пользователя, не изобретать своё растяжение звука.
- **Чтение зоны по хоткею:** снимок зоны → OCR (с вариантами при низкой уверенности) → определение говорящего по настройкам зоны → TextPreparer → голос по `voice` зоны. Автомат 4.4 не используется, `repeat_cooldown_min` не действует.
- Хоткей «пропустить» обрывает текущую фразу с затуханием; «повторить» заново проигрывает последнюю озвученную реплику (из любой зоны, из кеша).
- Приглушение не снимается между фразами, если следующая начинается раньше, чем через `duck_release_ms` после конца предыдущей.

### 4.10 Звук
- Воспроизведение через `sounddevice`, выбор устройства вывода в настройках (по умолчанию системное).
- **Ducking** через `pycaw` (ISimpleAudioVolume): приглушаются аудиосессии **процесса окна игры и всех процессов с тем же именем exe** (у некоторых игр звук идёт из дочернего процесса). Понижение до `duck_level` (40%) с плавным переходом `duck_fade_ms` (150 мс), возврат через `duck_release_ms` (300 мс) после конца фразы. Приглушается только для реплик зон с `duck = true` и для ручных реплик.
- **Гарантированное восстановление громкости** игры: при штатном выходе, при исключении, при закрытии игры. Громкость сессий Windows сохраняется между перезагрузками — если не восстановить, игра навсегда останется тихой. Исходная громкость каждой сессии запоминается один раз при первом ducking (а не перед каждым) и **сразу пишется на диск** в `%APPDATA%/SubtitleVoicer/ducking_state.json` (`{exe: исходная громкость}`). При старте приложения, если файл не пуст, громкость восстанавливается для всех найденных сессий этих exe, после чего файл очищается.
- Сессии в эксклюзивном режиме не управляются — ducking молча не работает, приложение не падает.

### 4.11 Профили и определение игры
**Идентичность профиля:** `exe` (имя файла, без учёта регистра; может быть `null` у игры из библиотеки, ещё не запускавшейся) + `install_dir` (папка установки, если известна; иначе `null`). Имя файла профиля: `profiles/<exe>.json`, а если профилей с таким exe несколько — `profiles/<exe>--<первые 8 символов sha1(install_dir)>.json`.

**Какой профиль подходит процессу:**
1. Профили с тем же `exe`: если среди них есть с `install_dir`, в которой лежит exe процесса, — он; иначе профиль этого `exe` без `install_dir`.
2. Нет по `exe`, но есть профиль с `exe = null`, в `install_dir` которого лежит exe процесса, и окно процесса на весь монитор → профиль **привязывается**: в него записывается `exe`, пользователю — уведомление «Игра <имя> привязана».

**GameWatcher** раз в секунду смотрит процесс окна переднего плана (`psutil` + `pywin32`):
- есть подходящий профиль → он становится активным (см. правило фокуса в 4.1); если у него нет раскладки для текущего соотношения сторон → уведомление «Настройте зоны для этой игры»;
- профиля нет → предложение «создать профиль?» показывается, **только если** выполнены все условия:
  1. окно занимает весь монитор (полноэкранное или borderless: прямоугольник окна совпадает с прямоугольником монитора с точностью ±2 px);
  2. exe не в списке исключений `excluded_exes`;
  3. для этого exe ещё не спрашивали в текущем запуске приложения, и он не в списке «не спрашивать» `never_ask_exes` (кнопка в уведомлении).

**Соотношение сторон** определяется по размеру кадра и округляется до ближайшего из `16:9`, `16:10`, `21:9`, `32:9`, `4:3` (если отклонение > 3% — ключ вида `2560x1080`). Зоны хранятся отдельно для каждого соотношения. Если для текущего соотношения раскладки нет — озвучка не работает (другие соотношения **не** подставляются).

**Импорт/экспорт профиля** — один JSON-файл.

**Миграции формата.** `schema_version` — целое число, текущее значение — константа в коде. При загрузке профиля со старой версией применяются по очереди функции миграции `vN → vN+1` (каждая — отдельная чистая функция над словарём, с юнит-тестом на пример старого файла). Перед записью мигрированного профиля старый файл копируется в `profiles/backup/<имя>.v<N>.json`. Профиль **новее**, чем знает приложение, не загружается и не перезаписывается — уведомление «профиль создан более новой версией». Любое изменение формата профиля или настроек в будущих этапах = новая версия + миграция.

**Резервные копии.** Перед каждым сохранением профиля текущий файл копируется в `profiles/backup/<имя>.<дата-время>.json`; хранятся 5 последних копий на профиль. Запись профиля — атомарная: сначала во временный файл, потом замена.

### 4.12 Горячие клавиши
Глобальные, настраиваемые (формат `pynput`, например `<ctrl>+<alt>+p`).

| Действие | По умолчанию | Когда доступно |
|---|---|---|
| Пауза / продолжить автоозвучку | Ctrl+Alt+P | всегда |
| Повторить последнюю реплику | Ctrl+Alt+R | всегда |
| Пропустить текущую | Ctrl+Alt+S | всегда |
| Выделить область и прочитать один раз | Ctrl+Alt+A | когда есть активная игра |
| Настроить зоны профиля (редактор поверх игры) | Ctrl+Alt+Z | когда есть активная игра |
| Сохранить кадр для отладки | Ctrl+Alt+D | только в режиме разработчика |

**Хоткеи зон** задаются в самой зоне (`trigger = hotkey`, по умолчанию предлагаются Ctrl+Alt+1…9). Регистрируются, только пока профиль активен. При назначении — проверка на конфликт с общими хоткеями и с хоткеями других зон этого профиля; конфликт подсвечивается, сохранить нельзя.

### 4.13 Интерфейс (PySide6)
Вид интерфейса — по макетам `docs/design/*.html` (оглавление — `docs/design/index.html`) и правилам `docs/UI.md` (цвета, шрифты, размеры, компоненты и как их сделать в Qt). Этот раздел описывает, **что** есть в интерфейсе, `docs/UI.md` — **как** это выглядит.

- **Трей:** статус и текущая игра, вкл/выкл автоозвучки, «Повторить последнюю», «Настроить зоны», подменю **«Последние реплики»** (5 последних фраз), «Настройки…», «Выход». Меню трея — обычное меню Qt (`QMenu`): в подменю каждая фраза — один пункт (говорящий и начало текста); клик открывает **окно реплики** (4.13.1).
- **Окно настроек**, вкладки:
  - **Общие** — устройство вывода, громкость озвучки, базовая скорость, ducking, частота опроса, автозапуск; блок «Дополнительно»: список `excluded_exes` и `never_ask_exes`, **режим разработчика**;
  - **Профили и голоса** — список игр (иконка, название, статус «настроено» / «нет зон для 16:9» / «не настроено»), кнопки «Добавить игру» (с этапа 9), «Импорт/экспорт профиля»; для выбранного профиля: «Настроить зоны» (только при запущенной игре), «Настроить по скриншоту», список зон с поведением и хоткеями, голоса рассказчика и по умолчанию, таблица персонажей (имя и варианты, пол, голос, как назначен; прослушать, изменить, объединить, удалить, добавить, импорт из текста), словарь произношений (добавить, изменить, удалить, **прослушать**), стоп-лист имён;
  - **Горячие клавиши** — общие хоткеи из 4.12;
  - **История** — **только в режиме разработчика** (4.13.2).
- **Редактор зон** — два режима:
  - **поверх игры** (хоткей Ctrl+Alt+Z): замороженный кадр на весь монитор игры;
  - **по скриншоту**: обычное окно с выбранной картинкой. Картинка должна быть **полным кадром игры**: если её соотношение сторон не из списка 4.11 (±3%) — предупреждение, что зоны могут съехать. Для JPEG — предупреждение, что цвета могут быть неточными (сжатие, кадры из видео), и их стоит проверить в игре. Раскладка определяется по размеру картинки.
  - В обоих режимах: слева на кадре — прямоугольники зон (выделение мышью, перемещение, углы); панель со **списком зон** и кнопкой «Добавить зону» (выбор шаблона 4.2); для выбранной зоны — имя, поведение, хоткей, приоритет, голос, способ определения говорящего, «не повторять N минут», «приглушать игру», пресет маски и цвета пипеткой; живой предпросмотр маски и распознанного текста с разбором говорящего; кнопка «Прослушать».
- **Уведомления** (всплывающие окна у трея): «Похоже, это новая игра — создать профиль?» (кнопки «Создать профиль» / «Не спрашивать»), «Настройте зоны для этой игры», «Игра привязана».

#### 4.13.1 Окно реплики и исправление произношения
- Окно реплики: говорящий, полный текст, кнопки «Повторить» и «Исправить произношение».
- Исправление произношения: текст реплики, где каждое слово — кнопка. Клик по слову открывает форму записи словаря с `from` = это слово; рядом переключатель «все формы слова» (по умолчанию включён для слов длиннее 4 букв: тогда `from` = слово без последних 1–2 букв окончания + `*`, пользователь может поправить основу), поле `to`, кнопки «Прослушать» (синтез фразы с новой записью, без сохранения) и «Сохранить» (запись в словарь активного профиля). Прослушивание — ручная реплика по 4.9.

#### 4.13.2 Режим разработчика
Настройка `dev_mode` (по умолчанию выкл). Когда включена:
- вкладка **История**: последние `history_size` (50) реплик с метриками — время, зона, говорящий и почему выбран голос, текст до и после TextPreparer, уверенность OCR, какой вариант входа OCR сработал, задержка по 6, приоритет и чем закончилась (дозвучала / оборвана / отброшена);
- настройка отладочного оверлея (рамки зон, состояние автомата, последний распознанный текст, метрики поверх игры; окно прозрачно для кликов);
- хоткей Ctrl+Alt+D: сохраняет в `captures/<дата-время>/` **полный кадр** (`frame.png`), кропы и маски всех активных зон, JSON с результатами OCR. Полный кадр годится для редактора по скриншоту.

Когда `dev_mode` выключен — ничего из этого не видно и хоткей не регистрируется.

### 4.14 Первый запуск и хранение данных
- Все данные в `%APPDATA%/SubtitleVoicer/` (через `platformdirs`):
  - `settings.toml` — общие настройки;
  - `profiles/*.json` — профили;
  - `icons/` — иконки игр (этап 9);
  - `models/` — модели OCR и TTS;
  - `logs/` — логи с ротацией;
  - `captures/` — кадры из хоткея отладки.
- При первом запуске модели скачиваются автоматически с прогрессом и проверкой SHA-256. Повторно не качаются. **До этапа 8** модели загружаются встроенными механизмами самих библиотек (кеш RapidOCR, кеш Silero/torch.hub) — свой загрузчик не пишется; на этапе 8 загрузка переводится в `models/`.
- Автозапуск с Windows — настраиваемый (по умолчанию выкл), через ключ реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Логирование — стандартный `logging`, файл с ротацией (`RotatingFileHandler`, 5 × 2 МБ) + вывод в консоль в CLI-режиме. Необработанные исключения любого потока пишутся в лог (`sys.excepthook`, `threading.excepthook`).
- **Один экземпляр.** При старте приложение создаёт именованный мьютекс Windows `SubtitleVoicer.SingleInstance`. Если он уже существует — второй экземпляр выводит на передний план окно первого (или его меню трея) и завершается, ничего не озвучивая и не трогая громкость. CLI-команды `watch` и `run` подчиняются тому же правилу; `characters import/merge` — нет (не озвучивают).
- **Когда применяются настройки.** Все настройки и правки профиля применяются **сразу**, без перезапуска: со следующего кадра / следующей реплики. Исключения: смена движка TTS или OCR и смена устройства вывода — движок/устройство перезагружается в фоне, на это время озвучка приостанавливается, пользователю — короткое уведомление.

**Ключи `settings.toml`** (pydantic-модель `Settings`; других ключей не добавлять без правки ТЗ):

### 4.16 Библиотека игр (этап 9)
- **Поиск установленных игр** (при старте и по кнопке «Обновить»), источники из `library_sources`:
  - **Steam** — пути библиотек из `libraryfolders.vdf`, игры из `appmanifest_*.acf` (название, папка установки). Имя exe Steam не хранит → профиль создаётся с `exe = null` и привязывается при первом запуске (4.11);
  - **Epic Games** — JSON-манифесты `*.item` в `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests` (название, папка, исполняемый файл);
  - **GOG** — записи в реестре `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games` (название, папка, exe).
  - Форматы и пути проверить по актуальным файлам на машине пользователя, не по памяти. Источник, который не найден или не читается, пропускается с записью в лог.
- Найденные игры появляются в списке профилей как профили **без раскладок** (статус «не настроено»). Инструменты, редакторы и служебные записи (Steamworks Common Redistributables, SDK и т.п.) отфильтровываются по списку `resources/library_ignore.txt`.
- **Добавить игру вручную:** выбор exe → название из свойств файла (ProductName, иначе имя файла), `install_dir` = папка exe, иконка из exe.
- **Иконки:** извлекаются из exe средствами Windows API и кешируются в `icons/` как PNG. Для Steam-игр, если в локальном кеше Steam есть обложка, можно использовать её. Интернет не используется.
- Удаление игры из списка удаляет только профиль, не игру.

### 4.17 Хуки к движку игры (этап 11)
Текст берётся не с экрана, а напрямую из процесса игры через LunaHook (`lunahook-py`). Здесь зафиксировано то, что влияет на структуру уже сейчас; детали уточняются перед этапом 11.
- **Отдельный процесс.** Хуки работают в отдельном вспомогательном процессе (`python -m subvoicer.engines.hook.host`), основное приложение общается с ним через stdin/stdout строками JSON. Причины: внедрение DLL требует прав администратора — повышаются права только у вспомогательного процесса, а не у всего приложения; падение хука или игры не роняет приложение.
- **Каналы.** LunaHook находит в игре несколько потоков текста (диалоги, имена, интерфейс, мусор). Пользователь один раз назначает потокам роли в профиле: `hooks.channels` — список `{hook_code, name, role: "text" | "speaker" | "ignore", policy}`, где `policy` — та же `VoicingPolicy`, что у зон (4.2). Канал с ролью `speaker` даёт имя говорящего для текстового канала (аналог зоны вида `speaker`).
- **Дальше — общий путь:** текст канала → фильтр мусора → общий модуль обработки результата (4.4, включая защиту от двойной озвучки) → говорящий (4.5; для хуков — режимы `prefix`, `channel` и `none`) → подготовка текста → планировщик. Стабилизатор по маскам для хуков не нужен.
- **Античит.** Хуки не включаются, если: у профиля `hooks.enabled != true`; exe в списке `resources/anticheat_games.txt`; в системе запущен процесс известного античита (список в том же файле, например `EasyAntiCheat.exe`, `BEService.exe`). Проверка — при каждом подключении. Отказ — понятное уведомление, без попытки внедрения.
- **Разрядность.** Поддерживаются 32- и 64-битные игры (так заявлено у `lunahook-py`; проверить на этапе 11).
- **Лицензия.** LunaHook распространяется под GPL; до этапа 11 проверить лицензию `lunahook-py` и её последствия для сборки `.exe` (этап 12). Для личного использования ограничений нет.
- **UI (этап 11):** вкладка профиля «Текст из игры» — список найденных потоков с живым примером текста, выбор роли и политики озвучки.

## 5. Архитектура

### 5.1 Поток данных

```
 [CaptureThread]  windows-capture (WGC) → слот «последний кадр»
        │
        ▼
 [ZoneWorker] poll_hz, для каждой зоны auto: вырезка → маска → изменилась / пустая?
        │
        ▼
 [Stability] автомат 4.4 зоны (по маске) решает, когда звать OCR
        │ пора
        ▼
     OCR (RapidOCR, onnxruntime отпускает GIL) → фильтр мусора
        │
        ▼
 [Dedup] обработка результата (общая для всех источников): новая / продолжение / та же / недавно / дубль
        │
        ▼
 [SpeakerResolver] префикс / зона / цвет / нет → проверка имени → персонаж
        │
        ▼
 [TextPreparer] убрать имя, словарь, числа, латиница, ударения
        │
        ▼
 [SpeechScheduler] приоритеты, обрыв / очередь / продолжение, ускорение, пауза для ручных
        │
        ▼
 [TtsWorker] Silero (CPU) + кеш  →  [AudioPlayer] sounddevice  ⇄  [Ducker] pycaw

 Хоткеи зон, «выделить и прочитать», «повторить», прослушивание
        → снимок → OCR → SpeakerResolver → TextPreparer → SpeechScheduler (ручной приоритет)
```

- Стадии связаны через `queue.Queue` и события. Каждая стадия — отдельный поток; тяжёлые вызовы (onnxruntime, torch) отпускают GIL.
- GUI (Qt) в главном потоке, получает события через Qt-сигналы. Бизнес-логика от Qt не зависит.
- `GameWatcher` (отдельный поток, 1 Гц) следит за окном переднего плана и переключает профиль.

### 5.2 Слои и модули
Полное описание — **`docs/ARCHITECTURE.md`**: слои, правила зависимостей (проверяются `import-linter`), дерево папок, реестр движков, шина событий, рецепты расширения. Кратко:
- `core/` — модели, события, порты (`Protocol`); `config/` — настройки и профили;
- `pipeline/` — чистые алгоритмы без потоков, файлов, Windows и Qt (маски, OCR-логика, стабилизатор, говорящий, подготовка текста, планировщик);
- `engines/` — адаптеры к библиотекам и ОС (захват, OCR, TTS, звук, окна, хоткеи, библиотека игр); **только здесь** Windows-модули;
- `sources/` — откуда берутся реплики (OCR по зонам, ручное чтение, позже хуки);
- `services/` — потоки и очереди; `app/` — сборка, жизненный цикл, шина событий, фасад для UI и CLI;
- `ui/` — PySide6, **только здесь** Qt; `resources/` — данные по умолчанию.

### 5.3 Ключевые интерфейсы (черновик)

```python
class FrameSource(Protocol):
    def start(self, hwnd: int) -> None: ...
    def latest(self) -> Frame | None: ...        # BGRA numpy + размер кадра + timestamp
    def stop(self) -> None: ...

class OcrEngine(Protocol):
    def recognize(self, image: np.ndarray) -> OcrResult: ...  # строки: text, confidence, bbox

class TtsEngine(Protocol):
    name: str
    def voices(self) -> list[Voice]: ...          # id, пол, отображаемое имя
    def synthesize(self, text: str, voice_id: str, rate: float) -> Audio: ...  # float32 + sample_rate

class Ducker(Protocol):
    def duck(self, pid: int) -> None: ...
    def restore(self, pid: int) -> None: ...
    def restore_all(self) -> None: ...            # вызывается при любом выходе

class GameLibrarySource(Protocol):               # этап 9
    name: str
    def scan(self) -> list[FoundGame]: ...        # title, install_dir, exe | None, icon_path | None

class StressMarker(Protocol):                    # silero-stress
    def mark(self, text: str) -> str: ...         # расставляет «+», не трогая слова, где «+» уже есть

class TextSource(Protocol):                      # OCR по зонам, ручное чтение, позже хуки
    def start(self) -> None: ...
    def stop(self) -> None: ...                   # реплики публикует в очередь/шину сам

class Clock(Protocol):                           # всё, что зависит от времени; в тестах FakeClock
    def now(self) -> float: ...                   # секунды, монотонно
```

Полный список портов и требования к движкам (id, возможности, `is_available()`, ленивая загрузка) — `docs/ARCHITECTURE.md`, разделы 4–5.

Позже для хуков добавляется абстракция `TextSource`, выдающая реплики напрямую, минуя capture/vision/ocr.

## 6. Нефункциональные требования

| Требование | Цель |
|---|---|
| Задержка: субтитр появился → голос начался | медиана ≤ 700 мс, 95-й перцентиль ≤ 1.2 с. Замер: от времени кадра, на котором маска впервые изменилась (`t_change` из 4.4), до момента начала воспроизведения первого аудиобуфера; обе метки пишутся в DEBUG-лог с id реплики, скрипт `tools/latency_report.py` считает статистику по логу |
| Нагрузка на CPU во время игры | в среднем ≤ 10% (5800X) при 3 зонах `auto`, без запуска OCR при неизменной маске |
| Память | ≤ 1.5 ГБ |
| GPU | не используется по умолчанию |
| Надёжность | падение любого потока не роняет приложение; громкость игры всегда восстанавливается |
| Логи | уровни INFO/DEBUG, ротация, в DEBUG — время каждой стадии конвейера |
| Точность OCR (CER) | на синтетике, пресет `color` с правильным диапазоном цвета текста (как будет в реальном профиле): все изображения **с подложкой** — CER ≤ 2%; **без подложки** на фонах «шум» и «пёстрый» — CER ≤ 8%; фон «неон» — стресс-тест, цели нет, только отчёт. Остальные пресеты — только в отчёте. Реальные кадры — отслеживаем, цель уточнить после сбора фикстур |

## 9. Тестирование

- **Юнит-тесты** на чистую логику: автомат по маске (все строки таблицы 4.4), dedup (все пункты обработки результата, включая `repeat_cooldown_min` и дубль из другого источника), SpeakerResolver (все режимы, проверка имени, стоп-лист, нечёткое сопоставление), TextPreparer и словарь произношений (обычные записи, со звёздочкой, регулярки, порядок, защита `+` от перезаписи), SpeechScheduler (все правила 4.9 с приоритетами), эвристика пола, персонажи (назначение голоса, уточнение пола, объединение, импорт CSV), сопоставление процесса с профилем (4.11), модели профиля.
- **Синтетический набор** (`tools/gen_synthetic.py`) — изображения, имитирующие **кроп зоны субтитров** (не весь кадр), типичный размер 1200×120 и 1200×200 (одна и две строки):
  - **Фразы:** файл `tools/data/phrases_ru.txt`, ~200 строк, пишет исполнитель: реплики диалогов разной длины (от «Да.» до двух строк), с цифрами, с латиницей, с восклицаниями и многоточием; четверть — с префиксом имени (`Джуди: …`).
  - **Шрифты:** системные из `C:\Windows\Fonts` с кириллицей — `arial.ttf`, `arialbd.ttf`, `segoeui.ttf`, `segoeuib.ttf`, `tahoma.ttf`, `verdana.ttf`, `calibri.ttf`, `trebuc.ttf`; отсутствующие пропускаются. Никаких шрифтов из интернета.
  - **Текст:** белый, жёлтый, светло-голубой, бирюзовый; размер 28–48 px; варианты: без обводки, тёмная обводка 2 px, тень со смещением 2 px.
  - **Подложка:** нет / полупрозрачный чёрный прямоугольник (альфа 0.5 и 0.8).
  - **Фоны — только процедурные** (без картинок): однотонный тёмный, однотонный светлый, линейный градиент, шум, «пёстрый» (случайные цветные прямоугольники и круги + размытие), «неон» (тёмный фон + яркие цветные полосы и пятна того же цвета, что текст — стресс-тест).
  - Рядом с каждым `NNNN.png` — `NNNN.txt` с правильным текстом и `NNNN.json` с параметрами (категория для бенчмарка: `bg`, `backing`, `outline`, `color`).
  - Генерация детерминирована по `--seed`.
- **Реальные кадры:** `tests/fixtures/real/<игра>/*.png` + `.txt` с правильным текстом. Пополняются вручную и через хоткей отладки.
- **Бенчмарк OCR** (`tools/ocr_bench.py`): CER (расстояние Левенштейна по символам / длина правильного текста, после нормализации пробелов), доля отброшенных результатов, время на зону; разбивка по категориям из `.json`. Запускается вручную, результаты сравниваются между изменениями предобработки.
- **Контрактные тесты** (`tests/contracts/`): один набор тестов на порт, прогоняется для каждого движка семейства, доступного на машине (`docs/ARCHITECTURE.md`, раздел 7).
- **Время в тестах** — только через `FakeClock`; `time.sleep` в юнит-тестах запрещён.
- **Библиотека игр:** тесты разбора форматов Steam/Epic/GOG на образцах файлов в `tests/fixtures/library/` (образцы — минимальные, написанные вручную по реальным файлам пользователя).
- **Где запускаются тесты:** на Windows-машине пользователя. Тесты чистой логики не должны требовать Windows (чтобы работать где угодно), тесты Windows-частей помечаются `@pytest.mark.windows` и пропускаются на других ОС.
- **Ручные проверки** Windows-частей (захват, звук, ducking, хоткеи, библиотека) — чек-листы в критериях этапов.

## 10. Этапы реализации

Каждый этап заканчивается рабочим состоянием и коммитом. Следующий этап не начинается, пока критерии текущего не выполнены.

**Правило остановки.** Если критерий этапа не достигается после 3 осмысленных попыток (например, CER выше цели), исполнитель **останавливается**, показывает пользователю замеры и варианты и ждёт решения. Не снижать цели самостоятельно и не крутить параметры бесконечно.

**Ручные проверки.** Критерии, которые требуют игры, звука или глаз пользователя, исполнитель проверить не может: он готовит команду/инструкцию и просит пользователя проверить, этап закрывается после подтверждения.

### Этап 0. Каркас
- `pyproject.toml` (uv, `requires-python = ">=3.12,<3.13"`), каркас пакетов по `docs/ARCHITECTURE.md` (раздел 9, строка «0»), ruff, pytest, контракты `import-linter`, настройка логирования.
- `tools/smoke_stack.py`: импорт всех зависимостей раздела 7 (кроме `vdf`, он с этапа 9) с выводом версий; OCR одной сгенерированной на лету картинки с русским текстом (Pillow + системный шрифт); синтез одной фразы Silero в `smoke.wav`; перечень голосов модели. Модели загружаются встроенными средствами библиотек (4.14).
- Если какая-то зависимость не ставится на 3.12 — остановиться и сообщить пользователю, не менять версию Python и не заменять библиотеку самостоятельно.
- `torch` — только CPU-сборка. Если `uv sync` тянет CUDA-вариант, подключить индекс `https://download.pytorch.org/whl/cpu` для пакета `torch` через `[tool.uv.sources]`.
- `uv.lock` коммитится.
- **CI не используется** (личный проект). Проверки перед коммитом — локально: `ruff check`, `ruff format --check`, `lint-imports`, `pytest`. Тесты, которым нужны скачанные модели, помечаются `@pytest.mark.models` (быстрый прогон без них: `pytest -m "not models"`); тесты Windows-частей — `@pytest.mark.windows`.
- `docs/STATUS.md` и `docs/DECISIONS.md` уже есть — обновлять по правилам `CLAUDE.md`.

**Готово, когда:** `uv sync` на Python 3.12 проходит; `smoke_stack.py` выводит версии и создаёт wav с речью; `uv run pytest` зелёный (хотя бы пустой тест); `ruff check` чистый; `uv run lint-imports` проходит, и специально добавленный запрещённый импорт (например, `PySide6` в `pipeline/`) его валит (проверить и откатить).

### Этап 1. Синтетика и OCR
- Генератор синтетических субтитров (раздел 9) и файл фраз.
- Модуль `vision/` (пресеты масок, детекция изменений, пустота) и `ocr/` (RapidOCR PP-OCRv5: модели `cyrillic` и `eslav`, три варианта входа, варианты при низкой уверенности, фильтр мусора).
- Бенчмарк OCR: для каждой из двух моделей распознавания (`cyrillic`, `eslav`) и для каждого изображения — пресет `color` с диапазоном, построенным из известного цвета текста (H ±10, S и V ±80 от цвета текста с обрезкой по границам 0–179 / 0–255; H по кругу — при выходе за 0 или 179 диапазон делится на два), плюс пресет `bright_on_dark`; для каждого — три варианта входа (4.3). Отчёт: CER, доля отброшенных, среднее время — по категориям `bg` × `backing`.
- Записать в 4.3 выбранные по замеру модель распознавания и вариант входа по умолчанию.

**Готово, когда:** генератор создаёт ≥ 300 изображений с правильными ответами; бенчмарк выдаёт отчёт по категориям; цели CER из раздела 6 достигнуты; среднее время OCR одной зоны 1200×120 ≤ 100 мс на CPU (без учёта первого прогрева модели); юнит-тесты `vision/` (пустая маска, изменение маски на движущемся фоне без смены текста не срабатывает) зелёные.

### Этап 2. Захват и конвейер текста (без звука)
- `capture/` (WGC окна по hwnd, fallback DXGI), DPI awareness (4.1).
- Детекция изменений по маске, автомат стабилизации (4.4, включая `repeat_cooldown_min`), SpeakerResolver в режимах `prefix` и `none` с проверкой имени и стоп-листом (4.5; сопоставление с персонажами — на этапе 5).
- CLI-команда (одна зона, поведение `auto`):
  ```
  uv run python -m subvoicer.cli watch --exe chrome.exe --title "YouTube" \
      --rect 0.2,0.82,0.8,0.95 --preset bright_on_dark [--speaker prefix] [--debug]
  ```
  Окно выбирается по имени exe процесса; если окон несколько — по подстроке `--title` в заголовке; если всё равно несколько или ни одного — вывести список найденных окон (hwnd, exe, заголовок) и выйти с ошибкой. `--rect` — `x1,y1,x2,y2` в долях кадра (как `rect` в профиле). Для пресета `color` — `--color-hsv "h1,s1,v1:h2,s2,v2"` (можно несколько раз). Каждая реплика печатается строкой `[время] [имя или -] текст`. С `--debug` — логи состояний автомата и вызовов OCR.
- Тестовый сценарий пользователя: летсплей GTA 5 / Cyberpunk в браузере на весь экран.

**Готово, когда:** на летсплее реплики печатаются по одной без дублей; при неизменном субтитре OCR не вызывается (видно в DEBUG-логе); посимвольно печатающийся текст выдаётся одной репликой; одинаковая реплика, появившаяся дважды через пустую зону, печатается дважды; фраза вида «Совет: …» печатается целиком без имени; после сна и пробуждения ПК и после смены разрешения захват восстанавливается сам; проверка HDR выполнена и записана в `docs/DECISIONS.md`; юнит-тесты автомата по маске, dedup и SpeakerResolver зелёные.

### Этап 3. Озвучка
- `tts/` (Silero v5_cis_base + silero-stress, кеш, SAPI5 fallback), `text/` (TextPreparer, словарь произношений 4.7.1 — движок словаря, данные пока из аргумента CLI/файла, эвристика пола), `audio/` плеер, `scheduler/` — **политика 4.9 целиком, включая приоритеты и ручные реплики** (в CLI пока одна зона, приоритеты проверяются юнит-тестами).
- `tools/voice_samples.py` и `voices.toml` (4.6) — после генерации образцов **попросить пользователя проставить пол**.
- CLI-команда `watch` из этапа 2 получает флаги `--speak` и `--dict путь.json` (записи словаря).
- `tools/latency_report.py` (раздел 6).
- Хоткеи минимум: пауза, повторить, пропустить.

**Готово, когда:** реплики из этапа 2 озвучиваются; медиана задержки ≤ 700 мс по `latency_report.py`; новая реплика обрывает старую с затуханием; продолжение встаёт в очередь, а не обрывает; исчезнувшая с экрана реплика дочитывается; автоускорение работает по правилу 4.9; числа и латиница читаются осмысленно; запись словаря со звёздочкой срабатывает на разных падежах; пользователь проставил пол голосов; юнит-тесты TextPreparer, словаря, эвристики пола и SpeechScheduler зелёные.

### Этап 4. Ducking
- `audio/ducker.py` через pycaw, восстановление при любом выходе; учитывается флаг `duck` реплики.

**Готово, когда:** звук игры плавно приглушается и возвращается; реплика с `duck = false` звук не трогает; после `kill` процесса приложения во время ducking при следующем запуске громкость игры восстанавливается (исходное значение хранится на диске); эксклюзивный режим не вызывает падения.

### Этап 5. Профили, зоны и персонажи
- pydantic-модели профиля (5.4), хранение, идентичность и сопоставление процесса с профилем (4.11), GameWatcher, автопереключение.

- CLI-команды:
  - `uv run python -m subvoicer.cli run` — работа по профилям без GUI (профили пока правятся в JSON);
  - `uv run python -m subvoicer.cli characters import <профиль> <файл.csv>` — импорт персонажей (4.6) с отчётом;
  - `uv run python -m subvoicer.cli characters merge <профиль> <имя A> <имя B>`.

**Готово, когда:** смена игры в фокусе переключает профиль, а уход фокуса на другой монитор озвучку не останавливает; две зоны `auto` с разными приоритетами ведут себя по 4.9 (например, цель задания ждёт, пока договорит диалог); цель задания с `repeat_cooldown_min` не повторяется; разные персонажи звучат разными стабильными голосами между перезапусками; ручная правка голоса не перезаписывается; «Джудн» из-за ошибки OCR попадает в персонажа «Джуди»; импорт CSV добавляет персонажей с полом, голоса назначаются при первой реплике; профиль экспортируется и импортируется одним файлом; предложение создать профиль не появляется для браузера и проводника; механизм миграций покрыт тестом на искусственной миграции (v0 → v1); при сохранении создаются резервные копии (не больше 5), а прерванная запись не портит профиль.
