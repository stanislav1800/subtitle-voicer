# ТЗ: Subtitle Voicer — автоозвучка игровых субтитров

Версия: 1.2 (сентябрь 2026)
Статус: утверждено, готово к реализации

> **Для исполнителя.** Это ТЗ написано так, чтобы по нему можно было работать без контекста обсуждения. Если что-то здесь не определено или противоречит друг другу — **не придумывай**, остановись и спроси. Значения по умолчанию (пороги, тайминги) — стартовые; их можно подстраивать по результатам замеров, но фиксировать изменения в этом файле.

## 1. Цель и рамки

**Цель.** Десктопное приложение для Windows, которое читает русские субтитры с экрана игры и озвучивает их локальным синтезом речи. Нужно для игр без русской озвучки, где читать субтитры неудобно, особенно в динамичных сценах.

**Рамки:**
- Только Windows 10/11 x64.
- Личное использование. Возможно, позже поделюсь с друзьями. Не продаётся.
- Субтитры в играх считаются **уже русскими**. Модуля перевода нет.
- Всё работает локально, без облачных API. Интернет нужен один раз, для скачивания моделей.
- Тяжёлые вычисления (OCR, TTS) работают на **CPU**, чтобы не отнимать ресурсы видеокарты у игры.

**Вне рамок (не делаем):**
- Перевод с других языков.
- Субтитры над головами NPC и субтитры радио (например, в Cyberpunk: отключаются в настройках игры).
- Другие ОС.
- Внедрение в процесс игры в MVP (хуки только на позднем этапе и только для офлайн-игр).

**Тестовые игры:** GTA 5 (субтитры без подложки — сложный случай), Cyberpunk 2077 (есть имя говорящего и настраиваемая подложка — лёгкий случай), плюс старые игры по ходу дела.

**Окружение пользователя:** Ryzen 7 5800X, RTX 3070 8 ГБ, несколько мониторов, игры в режиме «полноэкранное окно» (borderless).

## 2. Термины

| Термин | Значение |
|---|---|
| Профиль | Настройки для конкретной игры, привязанные к её exe |
| Зона | Прямоугольник на окне игры, в котором ищется текст. Формат `rect = [x1, y1, x2, y2]` — левый верхний и правый нижний углы в долях (0..1) от ширины и высоты **кадра захвата** |
| Тип зоны | `dialog` (автоозвучка), `speaker` (имя говорящего), `note` (читается по хоткею) |
| Маска текста | Бинарное изображение зоны, где остался только текст (фон отброшен) |
| Реплика | Стабилизированный текст диалога с (необязательным) именем говорящего |
| Движок TTS | Реализация синтеза речи за общим интерфейсом |

## 3. Сценарии использования

1. **Обычная игра.** Приложение сидит в трее. Запускаю игру, приложение по exe находит профиль и начинает работать. Появился субтитр — через ≤0.7 с звучит голос персонажа, игра приглушается, потом громкость плавно возвращается.
2. **Новая игра без профиля.** Приложение замечает игру в фокусе и предлагает создать профиль (уведомление в трее). Я жму хоткей настройки: кадр игры замирает, выделяю зону субтитров мышкой, выбираю тип, сразу вижу маску и распознанный текст, сохраняю.
3. **Записка.** Жму хоткей «прочитать записку». Если у профиля есть зона `note` — читается она. Если нет — кадр замирает, выделяю область, она читается один раз. Пока звучит записка, автоозвучка диалогов на паузе.
4. **Пропустил реплику.** Хоткей «повторить последнюю».
5. **Кривое распознавание.** Хоткей «сохранить кадр»: кадр зоны, маска и результат OCR сохраняются в `captures/`; потом я сам переношу нужные в `tests/fixtures/real/` и пишу правильный текст.

## 4. Функциональные требования

### 4.1 Источник кадров (capture)
- Захват **окна игры** (не монитора) через `windows-capture` (Windows Graphics Capture). Окно может быть на любом мониторе.
- Fallback: DXGI Desktop Duplication (`windows-capture` DXGI-режим или `dxcam`) для монитора, на котором находится окно, если WGC отдаёт чёрный кадр (эксклюзивный полноэкранный режим старых игр). Чёрный кадр = максимум яркости пикселей < 5; переключение на DXGI после 10 чёрных кадров подряд. Кадр монитора **обрезается до прямоугольника клиентской области окна**, чтобы «кадр захвата» имел тот же смысл, что и при WGC.
- Время кадра — `time.monotonic()` в момент получения кадра приложением (используется для замера задержки).
- Частота обработки зон по умолчанию 10 Гц (настраивается). Храним только последний кадр, старые выбрасываем.
- Переживает изменение размера окна и потерю окна (игра закрыта → стоп, без падения).
- **DPI.** Процесс приложения при старте объявляет Per-Monitor DPI Awareness v2 (`SetProcessDpiAwarenessContext`). Все координаты внутри приложения — в **физических пикселях кадра захвата**. Доли зон (`rect`) считаются от размеров кадра захвата, а не от логических координат Qt. Редактор зон переводит координаты мыши в физические пиксели кадра.
- **Фокус.** Захват и озвучка продолжаются, пока жив процесс игры с активным профилем, **независимо от того, в фокусе ли её окно** (игра на одном мониторе, мышь на другом — озвучка идёт). Активный профиль меняется, только когда в фокус попадает окно другой игры, у которой есть профиль.

### 4.2 Обработка зоны
Конвейер для каждой активной зоны `dialog` (в профиле их может быть несколько — у каждой свой автомат 4.4, все пишут реплики в общий планировщик):
1. Вырезка зоны по долям окна.
2. **Построение маски текста** по пресету профиля:
   - `color` — диапазоны цветов текста в HSV **в формате OpenCV** (H 0–179, S 0–255, V 0–255); можно несколько диапазонов;
   - `bright_on_dark` — светлый текст с тёмной обводкой/тенью: порог по яркости + морфологическое закрытие;
   - `dark_on_bright` — то же для тёмного текста;
   - `adaptive` — `cv2.adaptiveThreshold`.
   После пресета: удаление мелкого шума (связные компоненты площадью < 0.02% зоны).
3. **Детекция изменений по маске, а не по сырым пикселям.** Фон в катсценах двигается постоянно — сравнение сырых пикселей даст ложные срабатывания каждый кадр. Маска считается изменившейся, если доля отличающихся пикселей маски > 0.5% площади зоны (параметр `change_ratio`). OCR запускается только по правилам стабилизации (4.4).
4. Маска пустая, если доля белых пикселей < 0.1% площади зоны (параметр `empty_ratio`) → событие «зона опустела».

### 4.3 OCR
- Основной движок: `RapidOCR` (onnxruntime, CPU) с моделью **PP-OCRv5 cyrillic mobile** (PP-OCRv6 кириллицу не поддерживает).
- Fallback-движок: Windows.Media.Ocr (WinRT, язык ru-RU). Используется, если RapidOCR не инициализировался, или если в профиле явно задано `"ocr": {"engine": "winrt"}`.
- **Что подаётся на вход OCR** — определяется замером на этапе 1. Бенчмарк сравнивает три варианта: (а) исходный кроп зоны; (б) кроп, где всё вне маски (с расширением маски на 2 px) закрашено чёрным; (в) маска как чёрный текст на белом. Лучший по CER вариант становится входом по умолчанию для каждого пресета; результат замера и выбор записываются в этот раздел ТЗ. Апскейл ×2 (`INTER_CUBIC`), если высота строки текста < 32 px (параметр `ocr.upscale`).
- **Низкая уверенность** = средняя уверенность строк < 0.8. Тогда прогоняются до 2 оставшихся вариантов входа из списка выше, берётся результат с наибольшей средней уверенностью. Запускается только в рамках одного вызова OCR из автомата 4.4.
- **Фильтр мусора:** отбросить результат, если средняя уверенность < `ocr.min_confidence` (по умолчанию 0.6), или доля кириллицы среди букв < 60%, или длина текста (без пробелов и пунктуации) < 3 символов — кроме разрешённых коротких слов: «да», «нет», «ой», «ах», «эй», «ну», «ага», «угу», «ого», «ха», «ок», «я», «ты», «мы» (сравнение без учёта регистра и пунктуации).
- **Порядок строк:** сверху вниз, в пределах строки слева направо; строки склеиваются через пробел (для записок — через перевод строки, чтобы сохранить абзацы).
- Результат: строки с текстом, уверенностью и bbox.

### 4.4 Стабилизация и дедупликация
Для каждой зоны `dialog` — конечный автомат. Параметры: `stable_ms` = 200, `max_wait_ms` = 1500, `match_ratio` = 90 (rapidfuzz `ratio`).

| Состояние | Событие | Действие → новое состояние |
|---|---|---|
| `EMPTY` | маска стала непустой | запомнить время `t_change` → `CHANGING` |
| `CHANGING` | маска изменилась | обновить `t_last_change` → `CHANGING` |
| `CHANGING` | маска не менялась `stable_ms` **или** с `t_change` прошло `max_wait_ms` | **один** запуск OCR → обработка результата → `SHOWN` |
| `CHANGING` / `SHOWN` | маска опустела | `EMPTY`, флаг `was_empty = true` |
| `SHOWN` | маска изменилась | `t_change` = сейчас → `CHANGING` |

- `max_wait_ms` — предохранитель: если маска «дёргается» непрерывно (фон того же цвета, что текст, или очень длинный посимвольный вывод), OCR всё равно запускается.
- **Обработка результата OCR** (после фильтра мусора 4.3), `last` — последняя озвученная реплика зоны:
  1. Результат отброшен фильтром → ничего.
  2. `was_empty == true` → **новая реплика** (даже если текст совпадает с `last`: одинаковая фраза, сказанная дважды, озвучивается дважды). Сбросить `was_empty`.
  3. `len(text) > len(last) + 3` и `ratio(text[:len(last)], last) >= match_ratio` (по нормализованному тексту: нижний регистр, без пунктуации и лишних пробелов) → **продолжение**: озвучивается только часть `text` после первых `len(last)` символов, тем же голосом, что и `last` (говорящий не переопределяется) (см. 4.9). После этого `last = text`.
  4. `ratio(text, last) >= match_ratio` → тот же субтитр, ничего.
  5. Иначе → **новая реплика**.
  - При новой реплике `last = text`. Имя говорящего определяется по 4.5 только для новой реплики.

### 4.5 Определение говорящего
Способ задаётся в профиле (`speaker.mode`):
- `prefix` — имя в начале первой строки, отделено разделителем (по умолчанию регулярка `^([^:]{1,30}):\s*`);
- `zone` — отдельная зона типа `speaker`, привязанная к зоне `dialog` полем `speaker_zone_id`; OCR этой зоны выполняется вместе с OCR диалога;
- `color` — имя отличается цветом: строится **вторая маска** по `speaker_colors_hsv` в той же зоне, по ней отдельный OCR — его результат и есть имя; из маски текста диалога пиксели цвета имени исключаются;
- `none` — имени нет.

**Эвристика пола по тексту** (модуль `text/gender.py`, регулярки Python `re` с `re.IGNORECASE`, проверяется только текст текущей реплики без имени):
- женский: `\bя\s+(\w+)(ла|лась)\b`, `\b(\w+)(ла|лась)\s+я\b`, `\bя\s+(рада|готова|должна|уверена|согласна|одна|сама|виновата|знакома)\b`;
- мужской: `\bя\s+(\w+)(л|лся)\b`, `\b(\w+)(л|лся)\s+я\b`, `\bя\s+(рад|готов|должен|уверен|согласен|один|сам|виноват|знаком)\b`;
- для мужских шаблонов на `л` совпавшее слово отбрасывается, если оно в списке исключений (существительные на «-л»): стартовый список — пол, стол, зал, мел, вол, угол, посол, орёл, осёл, козёл, футбол, ангел, дятел, пепел, котёл, узел, тыл; список лежит в коде и дополняется;
- совпали мужские и женские одновременно или ни одного → пол не определён.

**Выбор голоса для реплики:**
1. Имя найдено → голос персонажа из профиля (4.6).
2. Имени нет → эвристика пола → голос по умолчанию этого пола (`default_voices`).
3. Пол не определён → голос рассказчика (`narrator_voice`).

### 4.6 Голоса персонажей
- Каждому имени — свой голос, хранится в профиле (`characters`), меняется вручную в GUI.
- **Новое имя** (нет в `characters`):
  - пол = эвристика пола по тексту первой реплики; если не определён → `unknown`;
  - голос = детерминированный выбор из списка голосов нужного пола (для `unknown` — из всех голосов, отсортированных по id): стартовый индекс `int(sha1(имя в нижнем регистре, utf-8).hexdigest(), 16) % n`; если этот голос уже назначен другому персонажу профиля — берётся следующий по списку (по кругу); если заняты все — стартовый;
  - запись сохраняется в профиль с флагом `"auto": true`.
- Если у персонажа `gender: unknown`, `auto: true`, и очередная его реплика даёт однозначный пол → пол обновляется, голос переназначается по тому же правилу. Записи с `auto: false` (правлены вручную) не меняются никогда.
- Голос рассказчика и голоса по умолчанию (М/Ж) задаются в профиле. **При создании профиля** они заполняются так: `narrator_voice` — первый по id голос с полом `male`, `default_voices.male` — второй мужской (или первый, если он один), `default_voices.female` — первый женский. Если голосов нужного пола нет — первый голос каталога.

**Каталог голосов** — файл `src/subvoicer/tts/voices.toml`: для каждого голоса движка `id`, `gender` (`male` / `female` / `unknown`), отображаемое имя. **Список id берётся из самой модели** (перечень спикеров, который отдаёт загруженная модель Silero), а не из примеров в этом ТЗ. Пол голосов исполнитель определить не может: на этапе 3 он создаёт `tools/voice_samples.py`, который синтезирует по одной фразе каждым голосом в `samples/<id>.wav`, заполняет `voices.toml` со значением `gender = "unknown"`, и **просит пользователя прослушать и проставить пол**. Пока разметки нет, все голоса `unknown` и работают правила выше для `unknown` — это ожидаемо и не ошибка.

### 4.7 Подготовка текста к синтезу
- Удаление имени говорящего из озвучиваемого текста.
- **Словарь произношений профиля:** замены с ударениями (`"Цири" → "Ц+ири"`), регулярки разрешены.
- Числа → словами (`num2words`, `lang="ru"`).
- Латиница: сначала словарь произношений профиля; затем аббревиатуры (слово из 2–5 заглавных латинских букв) — по названиям английских букв кириллицей («эй», «би», «си», «ди», …, таблица в коде); остальные латинские слова — побуквенная транслитерация по простой таблице (`a→а, b→б, c→к, ch→ч, sh→ш, …`).
- Ударения и омографы: `silero-stress`.
- Очистка: лишние пробелы, мусорные символы OCR (`|`, `_`, `~`, одиночные символы вне слов), многоточия → пауза.
- Длинный текст (записки) разбивается на предложения; синтез и воспроизведение идут потоково — первое предложение начинает звучать, пока синтезируются следующие.

### 4.8 Синтез речи (TTS)
- Общий интерфейс `TtsEngine` (см. 5.3).
- **Основной движок: Silero v5**, модель `v5_cis_base` (29 русских голосов, лицензия MIT) + пакет `silero-stress` (MIT) для ударений. Только CPU. Частота 48 кГц.
- Fallback: SAPI5 (системные голоса Windows). Используется, если Silero не инициализировался.
- Позже, опционально: Qwen3-TTS 0.6B на GPU (выключен по умолчанию).
- Кеш в памяти: последние ~200 синтезированных фраз, ключ = (текст, голос, скорость).

### 4.9 Политика озвучки (планировщик)
- **Новая реплика**, а текущая ещё звучит → текущая **обрывается** с затуханием ~100 мс, начинается новая.
- **Продолжение** (4.4, п.3) → не прерывает текущую фразу, а встаёт в очередь сразу за ней.
- Реплика исчезла с экрана до конца озвучки → **дочитывается** (исчезновение субтитра ничего не прерывает).
- **Автоускорение.** Счётчик `interrupts` — сколько реплик подряд были оборваны новыми. Скорость следующей реплики: `rate = base_rate × min(1.3, 1 + 0.15 × (interrupts − 1))` при `interrupts ≥ 2`, иначе `base_rate` (то есть ×1.15 после двух обрывов подряд, ×1.3 после трёх и более). Как только реплика дозвучала до конца, `interrupts = 0`. `base_rate` — настройка, по умолчанию 1.0.
- **Как меняется скорость:** средствами движка TTS (у Silero v5 — SSML `<prosody rate>`, проверить по документации). Если движок этого не поддерживает — остановиться и спросить пользователя, не изобретать своё растяжение звука.
- Чтение записки ставит автоозвучку на паузу (новые реплики диалога в это время отбрасываются, а не копятся); после записки автоозвучка продолжается. Записка читается **один раз, без автомата 4.4**: снимок зоны → OCR (с вариантами при низкой уверенности) → TextPreparer → голос рассказчика; говорящий не определяется. Если в момент нажатия звучит реплика — она обрывается.
- Хоткей «пропустить» обрывает текущую фразу с затуханием; «повторить» заново проигрывает последнюю озвученную реплику (из любой зоны, из кеша).
- Приглушение не снимается между фразами, если следующая начинается раньше, чем через 300 мс после конца предыдущей.

### 4.10 Звук
- Воспроизведение через `sounddevice`, выбор устройства вывода в настройках (по умолчанию системное).
- **Ducking** через `pycaw` (ISimpleAudioVolume): приглушаются аудиосессии **процесса окна игры и всех процессов с тем же именем exe** (у некоторых игр звук идёт из дочернего процесса). Понижение до 40% (настраивается) с плавным переходом ~150 мс, возврат через ~300 мс после конца фразы.
- **Гарантированное восстановление громкости** игры: при штатном выходе, при исключении, при закрытии игры. Громкость сессий Windows сохраняется между перезагрузками — если не восстановить, игра навсегда останется тихой. Исходная громкость каждой сессии запоминается один раз при первом ducking (а не перед каждым) и **сразу пишется на диск** в `%APPDATA%/SubtitleVoicer/ducking_state.json` (`{exe: исходная громкость}`). При старте приложения, если файл не пуст, громкость восстанавливается для всех найденных сессий этих exe, после чего файл очищается.
- Сессии в эксклюзивном режиме не управляются — ducking молча не работает, приложение не падает.

### 4.11 Профили
- Профиль привязан к имени exe игры (без учёта регистра).
- **GameWatcher** раз в секунду смотрит процесс окна переднего плана (`psutil` + `pywin32`):
  - есть профиль → он становится активным (см. правило фокуса в 4.1);
  - профиля нет → предложение «создать профиль?» показывается, **только если** выполнены все условия:
    1. окно занимает весь монитор (полноэкранное или borderless: прямоугольник окна совпадает с прямоугольником монитора с точностью ±2 px);
    2. exe не в списке исключений (по умолчанию: браузеры — `chrome.exe`, `msedge.exe`, `firefox.exe`, `opera.exe`, `browser.exe`; `explorer.exe`; мессенджеры — `Telegram.exe`, `Discord.exe`; плееры — `vlc.exe`, `mpc-hc64.exe`; список редактируется в настройках);
    3. для этого exe ещё не спрашивали в текущем запуске приложения, и он не в списке «не спрашивать» (кнопка в уведомлении).
- **Соотношение сторон** определяется по размеру кадра захвата и округляется до ближайшего из `16:9`, `16:10`, `21:9`, `32:9`, `4:3` (если отклонение > 3% — ключ вида `2560x1080`). Зоны хранятся отдельно для каждого соотношения. Если для текущего соотношения зон нет — уведомление «настройте зоны для этого разрешения», озвучка не работает (другие соотношения **не** подставляются).
- Импорт/экспорт профиля (один JSON-файл).

### 4.13 Интерфейс (PySide6)
- **Трей:** вкл/выкл, текущий профиль, открыть настройки, выход.
- **Окно настроек:** общие (устройство вывода, громкость озвучки, ducking, частота опроса, автозапуск, список exe-исключений и «не спрашивать» из 4.11), горячие клавиши, профили (список, импорт/экспорт), голоса персонажей текущего профиля с кнопкой прослушивания.
- **Редактор зон:** замороженный кадр игры поверх экрана, выделение прямоугольников мышкой, выбор типа зоны, настройка маски (пресет, цвета пипеткой), живой предпросмотр маски и распознанного текста.
- **Отладочный оверлей** (отключаемый, по умолчанию выкл): рамки зон и последний распознанный текст поверх игры.
- **История:** последние 50 реплик (говорящий, текст), кнопка «повторить».

### 4.14 Первый запуск и хранение данных
- Все данные в `%APPDATA%/SubtitleVoicer/` (через `platformdirs`):
  - `settings.toml` — общие настройки;
  - `profiles/<exe>.json` — профили;
  - `models/` — модели OCR и TTS;
  - `logs/` — логи с ротацией;
  - `captures/` — кадры из хоткея отладки.
- При первом запуске модели скачиваются автоматически с прогрессом и проверкой SHA-256. Повторно не качаются. **До этапа 8** модели загружаются встроенными механизмами самих библиотек (кеш RapidOCR, кеш Silero/torch.hub) — свой загрузчик не пишется; на этапе 8 загрузка переводится в `models/`.
- Автозапуск с Windows — настраиваемый (по умолчанию выкл), через ключ реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Логирование — стандартный `logging`, файл с ротацией (`RotatingFileHandler`, 5 × 2 МБ) + вывод в консоль в CLI-режиме.

**Ключи `settings.toml`** (pydantic-модель `Settings`; других ключей не добавлять без правки ТЗ):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | автоозвучка вкл/выкл |
| `poll_hz` | `10` | частота обработки зон |
| `output_device` | `""` | устройство вывода (`""` = системное) |
| `voice_volume` | `1.0` | громкость озвучки 0..1 |
| `base_rate` | `1.0` | базовая скорость речи |
| `duck_level` | `0.4` | до какой доли приглушать игру |
| `duck_fade_ms` / `duck_release_ms` | `150` / `300` | плавность / задержка возврата |
| `autostart` | `false` | запуск с Windows |
| `debug_overlay` | `false` | отладочный оверлей |
| `history_size` | `50` | размер истории реплик |
| `tts_cache_size` | `200` | размер кеша синтеза |
| `excluded_exes` | список из 4.11 | exe, для которых не предлагать профиль |
| `never_ask_exes` | `[]` | exe с отметкой «не спрашивать» |
| `hotkeys` | таблица 4.12 | действие → сочетание (формат pynput, например `<ctrl>+<alt>+p`) |

### 4.15 Точки входа
- До этапа 6 (GUI) приложение запускается как CLI: `uv run python -m subvoicer.cli <команда>` (команды описаны в этапах).
- С этапа 6: `uv run python -m subvoicer` запускает приложение с треем; CLI-команды остаются для отладки.

## 5. Архитектура

### 5.1 Поток данных

```
 [CaptureThread]  windows-capture (WGC) → слот «последний кадр»
        │
        ▼
 [ZoneWorker] poll_hz: вырезка зоны → маска → изменилась / пустая?
        │
        ▼
 [Stabilizer] автомат 4.4 решает, когда звать OCR
        │ пора
        ▼
     OCR (RapidOCR, onnxruntime отпускает GIL) → фильтр мусора
        │
        ▼
 [Stabilizer] обработка результата: новая / продолжение / та же
        │
        ▼
 [SpeakerResolver] префикс / зона / цвет / эвристика → (имя, пол)
        │
        ▼
 [TextPreparer] убрать имя, словарь произношений, числа, латиница, ударения
        │
        ▼
 [SpeechScheduler] политика: оборвать / дочитать / ускорить / пауза для записки
        │
        ▼
 [TtsWorker] Silero (CPU) + кеш  →  [AudioPlayer] sounddevice  ⇄  [Ducker] pycaw
```

- Стадии связаны через `queue.Queue` и события. Каждая стадия — отдельный поток; тяжёлые вызовы (onnxruntime, torch) отпускают GIL.
- GUI (Qt) в главном потоке, получает события через Qt-сигналы. Бизнес-логика от Qt не зависит.
- `GameWatcher` (отдельный поток, 1 Гц) следит за окном переднего плана и переключает профиль.

### 5.2 Модули (пакет `subvoicer`)

| Модуль | Ответственность | Зависит от Windows |
|---|---|---|
| `capture/` | Источники кадров (WGC, DXGI) | да |
| `vision/` | Вырезка зон, маски, детекция изменений | нет |
| `ocr/` | Движки OCR, фильтр мусора | частично (WinRT) |
| `pipeline/` | Stabilizer, SpeakerResolver, конвейер зон | нет |
| `text/` | Нормализация, словарь произношений, эвристика пола | нет |
| `tts/` | Движки TTS, кеш, загрузка моделей | нет (SAPI5 — да) |
| `audio/` | Плеер, Ducker | да |
| `scheduler/` | Политика озвучки | нет |
| `profiles/` | Модели pydantic, хранение, GameWatcher | частично |
| `hotkeys/` | Глобальные хоткеи | да |
| `ui/` | PySide6: трей, настройки, редактор зон, оверлей | да |
| `app.py` | Сборка всего вместе, жизненный цикл, восстановление громкости | — |

**Правило:** модули без Windows-зависимостей должны тестироваться на чистом pytest без запуска игры. Всё Windows-специфичное — за интерфейсами, в тестах подменяется фейками.

### 5.3 Ключевые интерфейсы (черновик)

```python
class FrameSource(Protocol):
    def start(self, hwnd: int) -> None: ...
    def latest(self) -> Frame | None: ...        # BGRA numpy + размер окна + timestamp
    def stop(self) -> None: ...

class OcrEngine(Protocol):
    def recognize(self, image: np.ndarray) -> OcrResult: ...  # строки: text, confidence, bbox

class TtsEngine(Protocol):
    name: str
    def voices(self) -> list[Voice]: ...          # id, пол, отображаемое имя
    def synthesize(self, text: str, voice_id: str, rate: float) -> Audio: ...  # float32 + sample_rate

class Ducker(Protocol):
    def duck(self, pid: int) -> None: ...
    def restore(self, pid: int) -> None: ...
    def restore_all(self) -> None: ...            # вызывается при любом выходе
```

Позже для хуков добавляется абстракция `TextSource`, выдающая реплики напрямую, минуя capture/vision/ocr.

### 5.4 Формат профиля (пример)

```json
{
  "schema_version": 1,
  "exe": "Cyberpunk2077.exe",
  "title": "Cyberpunk 2077",
  "layouts": {
    "16:9": {
      "zones": [
        {
          "id": "dialog",
          "type": "dialog",
          "rect": [0.20, 0.82, 0.80, 0.95],
          "mask": {
            "preset": "color",
            "colors_hsv": [[[80, 80, 150], [100, 255, 255]]],
            "speaker_colors_hsv": [[[0, 100, 150], [15, 255, 255]]]
          }
        },
        { "id": "note", "type": "note", "rect": [0.30, 0.15, 0.70, 0.80], "mask": { "preset": "adaptive" } }
      ]
    }
  },
  "speaker": { "mode": "prefix", "pattern": "^([^:]{1,30}):\\s*" },
  "narrator_voice": "ru_eduard",
  "default_voices": { "male": "ru_alexandr", "female": "ru_ekaterina" },
  "characters": {
    "Джуди": { "gender": "female", "voice": "ru_ramilia" },
    "Джонни": { "gender": "male", "voice": "ru_eduard" }
  },
  "pronunciation": [
    { "from": "Ви", "to": "В+и" },
    { "from": "\\bNCPD\\b", "to": "эн си пи ди", "regex": true }
  ],
  "ocr": { "min_confidence": 0.6, "upscale": 2.0 },
  "stabilization": { "stable_ms": 200, "max_wait_ms": 1500, "match_ratio": 90, "change_ratio": 0.005, "empty_ratio": 0.001 }
}
```

Цвета, прямоугольники и **id голосов выше — условные примеры**. Реальные цвета и зоны подбираются в редакторе зон, реальные id голосов берутся из `voices.toml` (4.6). Поле `characters.*.auto` в примере опущено (по умолчанию `false` для записей, созданных вручную).

Дополнительные поля, не показанные в примере:
- у зоны `dialog` при `speaker.mode = "zone"` — `"speaker_zone_id": "<id зоны типа speaker>"`;
- `"ocr": {"engine": "rapidocr" | "winrt"}` — по умолчанию `rapidocr`;
- у зоны — `"mask": {"preset": "bright_on_dark", "threshold": 200}` для пресетов порога (яркость 0–255, по умолчанию 200 для `bright_on_dark` и 60 для `dark_on_bright`).

Профиль хранится как pydantic-модель с `schema_version`; неизвестные поля при загрузке — ошибка валидации с понятным сообщением, а не молчаливый пропуск.

## 6. Нефункциональные требования

| Требование | Цель |
|---|---|
| Задержка: субтитр появился → голос начался | медиана ≤ 700 мс, 95-й перцентиль ≤ 1.2 с. Замер: от времени кадра, на котором маска впервые изменилась (`t_change` из 4.4), до момента начала воспроизведения первого аудиобуфера; обе метки пишутся в DEBUG-лог с id реплики, скрипт `tools/latency_report.py` считает статистику по логу |
| Нагрузка на CPU во время игры | в среднем ≤ 10% (5800X), без запуска OCR при неизменной маске |
| Память | ≤ 1.5 ГБ |
| GPU | не используется по умолчанию |
| Надёжность | падение любого потока не роняет приложение; громкость игры всегда восстанавливается |
| Логи | уровни INFO/DEBUG, ротация, в DEBUG — время каждой стадии конвейера |
| Точность OCR (CER) | на синтетике, пресет `color` с правильным диапазоном цвета текста (как будет в реальном профиле): все изображения **с подложкой** — CER ≤ 2%; **без подложки** на фонах «шум» и «пёстрый» — CER ≤ 8%; фон «неон» — стресс-тест, цели нет, только отчёт. Остальные пресеты — только в отчёте. Реальные кадры — отслеживаем, цель уточнить после сбора фикстур |

## 9. Тестирование

- **Юнит-тесты** на чистую логику: Stabilizer (посимвольный вывод, повтор реплики, дописывание), SpeakerResolver (все режимы), TextPreparer (числа, латиница, словарь), SpeechScheduler (оборвать/дочитать/ускорить/пауза), эвристика пола, модели профиля.
- **Синтетический набор** (`tools/gen_synthetic.py`) — изображения, имитирующие **кроп зоны субтитров** (не весь кадр), типичный размер 1200×120 и 1200×200 (одна и две строки):
  - **Фразы:** файл `tools/data/phrases_ru.txt`, ~200 строк, пишет исполнитель: реплики диалогов разной длины (от «Да.» до двух строк), с цифрами, с латиницей, с восклицаниями и многоточием; четверть — с префиксом имени (`Джуди: …`).
  - **Шрифты:** системные из `C:\Windows\Fonts` с кириллицей — `arial.ttf`, `arialbd.ttf`, `segoeui.ttf`, `segoeuib.ttf`, `tahoma.ttf`, `verdana.ttf`, `calibri.ttf`, `trebuc.ttf`; отсутствующие пропускаются. Никаких шрифтов из интернета.
  - **Текст:** белый, жёлтый, светло-голубой, бирюзовый; размер 28–48 px; варианты: без обводки, тёмная обводка 2 px, тень со смещением 2 px.
  - **Подложка:** нет / полупрозрачный чёрный прямоугольник (альфа 0.5 и 0.8).
  - **Фоны — только процедурные** (без картинок): однотонный тёмный, однотонный светлый, линейный градиент, шум, «пёстрый» (случайные цветные прямоугольники и круги + размытие), «неон» (тёмный фон + яркие цветные полосы и пятна того же цвета, что текст — стресс-тест).
  - Рядом с каждым `NNNN.png` — `NNNN.txt` с правильным текстом и `NNNN.json` с параметрами (категория для бенчмарка: `bg`, `backing`, `outline`, `color`).
  - Генерация детерминирована по `--seed`.
- **Реальные кадры:** `tests/fixtures/real/<игра>/*.png` + `.txt` с правильным текстом. Пополняются вручную и через хоткей отладки.
- **Бенчмарк OCR** (`tools/ocr_bench.py`): CER (расстояние Левенштейна по символам / длина правильного текста, после нормализации пробелов), доля отброшенных результатов, время на зону; разбивка по категориям из `.json`. Запускается вручную, результаты сравниваются между изменениями предобработки.
- **Где запускаются тесты:** на Windows-машине пользователя. Тесты чистой логики не должны требовать Windows (чтобы работать где угодно), тесты Windows-частей помечаются `@pytest.mark.windows` и пропускаются на других ОС.
- **Ручные проверки** Windows-частей (захват, звук, ducking, хоткеи) — чек-листы в критериях этапов.

## 10. Этапы реализации

Каждый этап заканчивается рабочим состоянием и коммитом. Следующий этап не начинается, пока критерии текущего не выполнены.

**Правило остановки.** Если критерий этапа не достигается после 3 осмысленных попыток (например, CER выше цели), исполнитель **останавливается**, показывает пользователю замеры и варианты и ждёт решения. Не снижать цели самостоятельно и не крутить параметры бесконечно.

**Ручные проверки.** Критерии, которые требуют игры, звука или глаз пользователя, исполнитель проверить не может: он готовит команду/инструкцию и просит пользователя проверить, этап закрывается после подтверждения.

### Этап 0. Каркас
- `pyproject.toml` (uv, `requires-python = ">=3.12,<3.13"`), структура пакетов из раздела 8 (пустые `__init__.py`), ruff, pytest, настройка логирования.
- `tools/smoke_stack.py`: импорт всех зависимостей раздела 7 с выводом версий; OCR одной сгенерированной на лету картинки с русским текстом (Pillow + системный шрифт); синтез одной фразы Silero в `smoke.wav`; перечень голосов модели. Модели загружаются встроенными средствами библиотек (4.14).
- Если какая-то зависимость не ставится на 3.12 — остановиться и сообщить пользователю, не менять версию Python и не заменять библиотеку самостоятельно.
- `torch` — только CPU-сборка. Если `uv sync` тянет CUDA-вариант, подключить индекс `https://download.pytorch.org/whl/cpu` для пакета `torch` через `[tool.uv.sources]`.

**Готово, когда:** `uv sync` на Python 3.12 проходит; `smoke_stack.py` выводит версии и создаёт wav с речью; `uv run pytest` зелёный (хотя бы пустой тест); `ruff check` чистый.

### Этап 1. Синтетика и OCR
- Генератор синтетических субтитров (раздел 9) и файл фраз.
- Модуль `vision/` (пресеты масок, детекция изменений, пустота) и `ocr/` (RapidOCR cyrillic, три варианта входа, варианты при низкой уверенности, фильтр мусора).
- Бенчмарк OCR: для каждого изображения — пресет `color` с диапазоном, построенным из известного цвета текста (±10 по H, S и V ≥ 80), плюс пресет `bright_on_dark`; для каждого — три варианта входа (4.3). Отчёт: CER, доля отброшенных, среднее время — по категориям `bg` × `backing`.
- Записать в 4.3 выбранный по замеру вариант входа по умолчанию.

**Готово, когда:** генератор создаёт ≥ 300 изображений с правильными ответами; бенчмарк выдаёт отчёт по категориям; цели CER из раздела 6 достигнуты; среднее время OCR одной зоны 1200×120 ≤ 100 мс на CPU (без учёта первого прогрева модели); юнит-тесты `vision/` (пустая маска, изменение маски на движущемся фоне без смены текста не срабатывает) зелёные.

### Этап 2. Захват и конвейер текста (без звука)
- `capture/` (WGC окна по hwnd, fallback DXGI), DPI awareness (4.1).
- Детекция изменений по маске, автомат стабилизации (4.4), SpeakerResolver (`prefix`, `none`).
- CLI-команда:
  ```
  uv run python -m subvoicer.cli watch --exe chrome.exe --title "YouTube" \
      --rect 0.2,0.82,0.8,0.95 --preset bright_on_dark [--speaker prefix] [--debug]
  ```
  Окно выбирается по имени exe процесса; если окон несколько — по подстроке `--title` в заголовке; если всё равно несколько или ни одного — вывести список найденных окон (hwnd, exe, заголовок) и выйти с ошибкой. `--rect` — `x1,y1,x2,y2` в долях кадра (как `rect` в профиле). Для пресета `color` — `--color-hsv "h1,s1,v1:h2,s2,v2"` (можно несколько раз). Каждая реплика печатается строкой `[время] [имя или -] текст`. С `--debug` — логи состояний автомата и вызовов OCR.
- Тестовый сценарий пользователя: летсплей GTA 5 / Cyberpunk в браузере на весь экран.

**Готово, когда:** на летсплее реплики печатаются по одной без дублей; при неизменном субтитре OCR не вызывается (видно в DEBUG-логе); посимвольно печатающийся текст выдаётся одной репликой; одинаковая реплика, появившаяся дважды через пустую зону, печатается дважды; юнит-тесты автомата стабилизации (все строки таблицы 4.4) и SpeakerResolver зелёные.

### Этап 3. Озвучка
- `tts/` (Silero v5_cis_base + silero-stress, кеш, SAPI5 fallback), `text/` (TextPreparer, эвристика пола), `audio/` плеер, `scheduler/`.
- `tools/voice_samples.py` и `voices.toml` (4.6) — после генерации образцов **попросить пользователя проставить пол**.
- CLI-команда `watch` из этапа 2 получает флаг `--speak`.
- `tools/latency_report.py` (раздел 6).
- Хоткеи минимум: пауза, повторить, пропустить.

**Готово, когда:** реплики из этапа 2 озвучиваются; медиана задержки ≤ 700 мс по `latency_report.py`; новая реплика обрывает старую с затуханием; продолжение встаёт в очередь, а не обрывает; исчезнувшая с экрана реплика дочитывается; автоускорение работает по правилу 4.9; числа и латиница читаются осмысленно; пользователь проставил пол голосов; юнит-тесты TextPreparer, эвристики пола и SpeechScheduler зелёные.

### Этап 4. Ducking
- `audio/ducker.py` через pycaw, восстановление при любом выходе.

**Готово, когда:** звук игры плавно приглушается и возвращается; после `kill` процесса приложения во время ducking при следующем запуске громкость игры восстанавливается (исходное значение хранится на диске); эксклюзивный режим не вызывает падения.

### Этап 5. Профили и голоса
- pydantic-модели профиля, хранение, GameWatcher с правилами 4.11, автопереключение.
- Говорящий: режимы `zone`, `color`; назначение голосов по 4.6; словарь произношений.
- CLI-команда `uv run python -m subvoicer.cli run` — работа по профилям без GUI (зоны пока задаются правкой JSON).

**Готово, когда:** смена игры в фокусе переключает профиль, а уход фокуса на другой монитор озвучку не останавливает; разные персонажи звучат разными стабильными голосами между перезапусками; ручная правка голоса не перезаписывается; словарь произношений применяется; профиль экспортируется и импортируется одним файлом; предложение создать профиль не появляется для браузера и проводника.

### Этап 6. Интерфейс
- Трей, окно настроек, редактор зон с живым предпросмотром маски и OCR, история, отладочный оверлей.
- Предложение создать профиль для новой игры.

**Готово, когда:** профиль для новой игры создаётся полностью из GUI, без правки JSON; все настройки из 4.13 доступны в окне; оверлей включается и выключается.

### Этап 7. Записки и отладка
- Хоткеи: прочитать записку, выделить область, сохранить кадр.
- Пауза автоозвучки на время записки.

**Готово, когда:** записка читается из зоны `note` и из произвольного выделения; автоозвучка на это время молчит и потом продолжается; хоткей отладки сохраняет кадр + маску + OCR-результат в `captures/`.

### Этап 8. Удобство
- Автоскачивание моделей при первом запуске с прогрессом и SHA-256.
- Автозапуск с Windows (настраиваемый).

**Готово, когда:** на чистой папке `%APPDATA%` приложение само скачивает модели и работает; галочка автозапуска реально включает/выключает запуск.

## 11. Известные риски

| Риск | Что делаем |
|---|---|
| Субтитры без подложки на ярком фоне (GTA 5) | Маска по цвету + обводке, несколько вариантов предобработки, фильтр мусора |
| Цвет субтитров зависит от настроек игры (режимы для дальтоников в Cyberpunk) | Цвета только из профиля, пипетка в редакторе зон |
| WGC отдаёт чёрный кадр в эксклюзивном полноэкранном режиме | Fallback DXGI; рекомендация играть в borderless |
| Игры с античитом | Только захват экрана; никаких инъекций в MVP |
| Громкость игры осталась пониженной после падения | Исходная громкость на диске + восстановление при следующем запуске |
| Большой размер torch | CPU-сборка torch; позже проверить ONNX-вариант Silero |
| Ударения в выдуманных именах | Словарь произношений профиля |
