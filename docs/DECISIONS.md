## Отладочный оверлей — над окном игры, а не над всеми окнами (2026-10-09)

- Пользователь: «странно выглядит, что что-то отрисовывается, пока смотришь на другое окно»; «MSI Afterburner выводит прямо в окне». Afterburner (RivaTuner) встраивает DLL в игру и рисует в её кадр — нам нельзя (CLAUDE.md: никаких инъекций до этапа 11; античиты). Сделано без встраивания: окно оверлея становится подчинённым окну игры (`GWLP_HWNDPARENT`, разрешено и для окна другого процесса) и перестаёт быть «поверх всех» — лежит сразу над игрой, любое окно поверх игры закрывает и его, сворачивается вместе с игрой. Проверено на Блокноте: владелец выставлен, `WS_EX_TOPMOST` снят, следующее окно под оверлеем — «игра». Отброшено (по решению пользователя): ещё и прятать оверлей, когда игра не в фокусе. Окно оверлея — ровно по картинке окна игры, а не на весь монитор: плашка в углу окна, ничего за его краями, при перемещении и изменении размера окна оверлей едет за ним (раз в 0,5 с). Уведомление «Настройте зоны» — один раз на игру за запуск (было — на каждую пару «игра + соотношение»: пока тянешь окно, каждый промежуточный размер давал новое, их набиралась стопка). Пропадание зон при изменении размера окна — не ошибка: зоны хранятся по соотношению сторон кадра (4.11), у окна 1834×1217 его раскладки нет. В эксклюзивном полноэкранном режиме обычные окна не видны — как и раньше.

## Голоса персонажей не только на NVIDIA; удаление с галочкой (2026-10-09, ТЗ 1.25)

- **Где работает движок** (пользователь: у друга Radeon, «чтобы он сам определял, что за видеокарта, и ставил то, что надо»): видеокарты читаются из Windows (WMI `Win32_VideoController`, встроенные тоже; виртуальные и «Microsoft Basic» отброшены), NVIDIA — по `nvidia-smi`. Три варианта движка, у каждого свой список пакетов в `resources/voice_convert/`: CUDA (как было), **ROCm** — torch от AMD для Windows (ROCm 7.2.1, torch 2.9.1, прямые ссылки на repo.radeon.com; только RX 7700–7900, PRO W7700–W7900, RX 9060–9070, AI PRO R9700 — gfx1100/1101/1200/1201 по таблице AMD; только Windows 11; драйвер 26.2.2+), **CPU** — torch для процессора. Отметка окружения (хеш списка) говорит, для чего оно собрано; формат настроек не менялся — выбор нужен только при установке движка. Если движок для видеокарты при запуске видит только процессор (старый драйвер AMD), голоса работают, а пользователю — уведомление.
- **Проверено на Python 3.12** (у меня, в отдельных папках): CUDA на RTX 3070 — +0,3–0,6 с к реплике, как на 3.11, окружение 5,0 ГБ; ROCm — пакеты AMD ставятся вместе с нашими, всё импортируется и преобразует (без карты AMD — на процессоре, втрое медленнее варианта CPU: torch от AMD не оптимизирован для процессора), окружение 5,3 ГБ; на самой карте Radeon проверяет друг пользователя.
- **Отброшено:** DirectML (заброшен с 2024 года, torch не новее 2.3 — наш transformers 5 и torch 2.11 не встанут); ZLUDA (неофициальная подмена CUDA, нестабильна с torch).
- **Замер на процессоре** (16 потоков, без игры; голос-основа Xenia): RVC (Ви) — реплика 2 с +2,2 с, 4 с +3,3–3,6 с, 8 с +5,5–5,7 с; so-vits (Цири) — +1,0 / +1,9 / +3,5 с. Запуск вспомогательного процесса 13–23 с, загрузка модели 3–8 с. Движок 1,3 ГБ (+0,5 ГБ моделей) против 5 ГБ для CUDA. Медленно, но оставлен по совету: включается только по желанию, лучше, чем никак; в интерфейсе — «медленно: +1–6 с к реплике». Под нагрузкой игры будет дольше.
- **Python движка 3.12 вместо 3.11** (пользователь: «почему 3.11, давай всё на 3.12»): причины 3.11 записано не было, пакеты движка допускают 3.12, а torch для ROCm под Windows есть только для 3.12. Версия Python входит в отметку окружения — движок на 3.11 пересобирается при следующей установке голоса. Сборка окружения теперь всегда с чистой папки (другая версия Python или torch поверх старого окружения не ставится).
- **Докачка:** `.part`, скачанный целиком, но не переименованный (файл был занят), раньше давал «HTTP 416» при попытке продолжить — теперь он проверяется по SHA-256 и просто переименовывается; на 416 файл качается заново.
- **Удаление программы — одно окно с галочкой** (пользователь: «думал, будет галочка, а не отдельное окно»): у деинсталлятора Inno Setup нет страниц мастера; `InitializeUninstall` вызывается раньше стандартного «Вы действительно хотите удалить?», поэтому показывается своё окно (галочка «Также удалить настройки, профили и скачанные модели», по умолчанию снята; «Удалить» / «Отмена»), а в `UninstallString` после установки записывается `unins000.exe /SILENT /ASK`: стандартный вопрос пропускается, `/ASK` показывает своё окно. Тихое удаление без `/ASK` ничего не спрашивает и данные оставляет. Проверено тестовым установщиком в отдельной папке: строка удаления записывается и не перезаписывается Inno Setup, окно появляется без стандартного вопроса, с пустой галочкой данные остаются.
- **Движок — отдельный шаг** (пользователь: «не чтобы вместе с первым голосом, а отдельно, голоса блокируем, пока не выбран движок… отменить, если выбрал процессор вместо видеокарты, удалить, если купил новую видеокарту»): в «Общих» строка «Движок» с выбором «Где работать», «Установить движок» / «Отмена» / «Удалить»; голоса серые, пока движка нет (удалить скачанный — можно); если движок на процессоре, а подходящая видеокарта найдена, — подсказка переустановить. Раньше «Скачать» у голоса на 88 МБ незаметно качало 5 ГБ движка. Заодно: «Отмена» в момент, когда последний файл докачался, раньше не останавливала установку (нашёл тест), и у выключенной основной кнопки не было серого вида в теме.
- **Прогресс установки пакетов движка:** uv не сообщает процент, полоса «бегала» 5–10 минут (пользователь: «так и должно быть?»). Теперь раз в 2 с считается размер кеша uv (папка на ~5 ГБ — 0,5 с) и показывается «скачано X из ~Y ГБ» по ожидаемому размеру движка; до конца шага не больше 99 %.
- **Урок:** мой тестовый `voices install --device cpu` записал в настоящую папку пользователя — песочница Claude не изолирует папку, созданную программой пользователя; движок пользователя оказался собран для процессора. Эксперименты — только в отдельном корне (`D:\svtest`).

## Этап 12 — установщик и голоса персонажей по одному (2026-10-08, ТЗ 1.24)

- **Установщик одним файлом** (пользователь: «как обычное приложение», «что из инета — потом докачать»): PyInstaller собирает папку (не «один exe» — тот распаковывал бы ~1 ГБ при каждом запуске; не Nuitka — долгая сборка и капризы с torch), Inno Setup упаковывает её в `SubtitleVoicer-Setup-<версия>.exe`. Замер: папка 983 МБ (torch 370, PySide6 92), установщик 353 МБ, сборка ~3 мин, установка 24 с. Ставится без прав администратора в `%LOCALAPPDATA%\Programs\SubtitleVoicer`; `AppMutex` — тот же мьютекс одного экземпляра, установщик просит закрыть запущенную программу; при удалении убирается запись автозапуска, данные в `%APPDATA%` остаются (проверено тихой установкой и удалением).
- **Сборка:** `mypy` попадал в сборку через хуки — исключены инструменты разработки; 32-битный компилятор Inno Setup не сжал ~1 ГБ в `lzma2/ultra64` («Out of memory») — `lzma2/max` в отдельном 64-битном процессе (`LZMAUseSeparateProcess`). PyInstaller не может пересоздать `dist\SubtitleVoicer`, если в ней стоит чей-то терминал. Ещё: правило `build/` в `.gitignore` скрыло бы `tools/build/` — правила привязаны к корню.
- **Голоса персонажей по одному** (пользователь: «не все разом, а по одному… возможность удалить… сколько весит»): общая часть — движок (окружение ~5 ГБ + RMVPE и ContentVec 0,56 ГБ) — ставится с первым голосом, удаляется отдельно; голос — 92–549 МБ. У so-vits после скачивания отрезается состояние оптимизатора: `load_checkpoint` so-vits-svc-fork читает только `model`, `iteration`, `learning_rate`; файл 549 → 183 МБ, преобразование совпало до нуля. Скачивание продолжается после отмены или обрыва (HTTP Range). Видеокарта — через `nvidia-smi` (torch приложения — CPU-сборка). Установка до ТЗ 1.24 (все голоса, архивы рядом) распознаётся без перекачки.
- **Запуск из установщика** (галочка «Запустить» в конце установки): вспомогательный процесс голосов падал — `uv trampoline failed to spawn Python child process: entity not found`; после перезапуска с ярлыка работал. У меня и у пользователя маленькая собранная программа запускала окружение нормально — разница в окружении процесса, который запустил установщик (временная папка установщика как рабочая). Рабочая папка оказалась ни при чём (её исправление оставлено как безвредное). Воспроизведено тестовым установщиком: Inno Setup включает защиту Windows RedirectionGuard, программы, запущенные установщиком, её наследуют и не проходят через junction, созданный без прав администратора; venv-«пересылка» uv вшивает путь к Python через junction `uv\python\cpython-3.11-windows-x86_64-none` (правка `home` в `pyvenv.cfg` не помогает), ошибка 448/2. Решение: установщик запускает программу через `explorer.exe` — её родитель уже работающий Проводник, защита не наследуется (проверено тестовым установщиком).
- **Что остаётся после удаления** (пользователь: «не всё удалилось»; замер у него: `%APPDATA%\SubtitleVoicer` 7,2 ГБ, общий кеш `uv` 8,3 ГБ, Python `uv` 0,1 ГБ): по решению пользователя (1) удаление спрашивает, удалить ли данные, по умолчанию «Нет» — переустановка находит профили и скачанное; тихое удаление данные не трогает; заодно `[UninstallDelete]` убирает папку программы целиком (`__pycache__` и прочее появившееся после установки); (2) движок голосов ставится `uv` со своими папками в `voice_convert/` (`UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_PREFERENCE=only-managed` — системный Python мог бы быть удалён и унести окружение), кеш пакетов удаляется сразу после установки, «Удалить движок» убирает и Python. Отброшено: чистить общий кеш `uv` (он может быть нужен пользователю для других программ). Окружение, поставленное раньше, не пересобирается (это 5 ГБ скачивания): оно работает на общем Python `uv` — чтобы перенести, удалить движок и скачать голос снова.
- **Запуск собранной программы:** первая загрузка Silero ~30 с после старта (в окружении разработки — быстрее; вероятно, проверка новых файлов антивирусом), дальше всё как в окружении разработки.

## Исправление слов OCR по словарю (2026-10-08, ТЗ 1.23)

- **Зачем:** в шрифте Cyberpunk 2077 OCR путает «а» и «о» («токое», «нодо», «пожалуйсто», «строшно») — Silero так и читает. Пользователь предложил сверку со словарём (Ожегов); Ожегов отброшен — в нём только начальные формы, а ошибки и в окончаниях. Взят частотный список словоформ из русских субтитров OpenSubtitles (FrequencyWords, Hermit Dave: код MIT, данные CC-BY-SA 4.0), 1,4 млн форм, файл закреплён за коммитом `f8a65e6`, скачивается при первом запуске (`models.toml`, `words_ru`, 29 МБ). Берутся формы с частотой ≥ 3 (535 тыс., ~60 МБ памяти, загрузка ~1–2,5 с в фоне при запуске); с порогом 20 (170 тыс.) пропадают нужные редкие формы («застывшем»).
- **Замер на текстах летсплея** (430 разных слов): правило 1 (нет в словаре → замены а↔о, меньше всего замен, затем частота) — 41 исправление, все верные после «меньше всего замен» (иначе «ночало→начала» вместо «начало»); правило 2 (вариант в 50 раз частотнее) — 14, все верные («ток→так», «кок→как», «доже→даже», «зо→за», «взяло→взяла» — говорит Эвелин); правило 3 (склейка, обе половины ≥ 1000) — «держит чип», «не любит», «он живёт», «надо узнать», «пор чувствую»; порог 1000 отсекает разрезы имён («Ёринобу→ери нобу» — 17, «Смэшер→см эшер» — 156); половина из 1–2 букв — только из списка служебных слов («Фотово» — OCR прочитал «Г» как «Ф» — иначе стало бы «Фото во»). ~2–13 мкс на слово. Не исправляются пары частых слов («Том/Там», «до/да», «Оно/Она»).
- **Вживую после включения** (летсплей, 45 реплик): текст заметно чище; остались пары частых слов («но/на», «До/Да»), название «Арасока» (нет в словаре — можно в словарь произношений профиля) и одна сильно испорченная строка. Нашёлся ещё случай «лесенки»: строка без имени (ответ Ви) появилась над репликой Джуди, текст начинался не с имени, по правилу 1.17 не делился — Джуди прозвучала второй раз. Правило 1.22 обобщено: текст не с имени, но с именами внутри и хотя бы одной репликой уже на экране, делится на реплики (часть до первого имени — без говорящего); срезанный верх — частный случай. «Он вышел. Джеки: …» без реплик на экране по-прежнему не делится.
- **«но/на», «до/да» по контексту** (пользователь попросил попробовать): корпуса пар слов для русского нет под рукой (FrequencyWords — только одиночные слова; модели языка — тяжело), поэтому правила по пунктуации и следующему слову, только `о → а` (шрифт делает из «а» «о», не наоборот): «до» перед знаком препинания / концом или перед «я, ты, он, она, оно, мы, вы, они, что, кто, ничего» → «да»; «но» не после запятой, тире, двоеточия и не в начале предложения → «на». На 223 текстах летсплея: 8 из 9 исправлений верные, ошибка — строка без двоеточия после имени («Джеки но завтра»); не исправляются «но» после запятой («Заряжен, но предохранителе», «понять, но что обращать») — нужен разбор грамматики.
- **Для всех игр по умолчанию** (решение пользователя), пары букв — настройка профиля `ocr.confusions` (по умолчанию а↔о); версия формата профиля 2, миграция включает `fix_words`. Имена персонажей профиля — известные слова: если персонаж записан с ошибкой («Ти-Бог» вместо «Ти-Баг»), текст приводится к этой записи — исправляется переименованием персонажа.

## Сдвоенные субтитры «лесенкой» (2026-10-07, ТЗ 1.22)

- **Как в Cyberpunk 2077:** новая реплика появляется строкой ниже со своим именем, старая поднимается и через пару секунд исчезает; длинная верхняя реплика бывает срезана краем зоны. Отсев дублей сравнивал текст зоны целиком, поэтому при сдвиге «лесенки» уже прозвучавшая реплика звучала снова, срезанный верх читался обрывком («реальностью… и не было!»), а имя в начале дописавшейся части («Ти-Баг: …») читалось голосом прежнего говорящего вместе с именем.
- **Решение (пользователь согласовал):** каждая реплика чтения сравнивается с репликами предыдущего чтения зоны — та же (сходство ≥ 90, без учёта имени: OCR путает «Ти-Бог»/«Ти-Баг»), её видимая часть (`partial_ratio`, кусок ≥ 12 символов) или она же с открывшимся началом (прежний кусок ≥ 40% и совпадает с концом) — не озвучивается; срезанный верх без имени перед именованной репликой отбрасывается; имя в начале продолжения начинает новую реплику; «продолжение», совпадающее с концом прежней строки, — та же строка, прочитанная OCR на пару букв длиннее. Правило ТЗ 1.17 «текст без имени в начале не делится» («Он вышел. Джеки: …») сохранено. Повтор после опустевшей зоны и реплика, вернувшаяся после другой, озвучиваются, как раньше.
- **Проверено на записи летсплея** (5 минут, 40 появлений субтитров, весь источник реплик приложения, 120 мс): было 48 озвучек — 7 повторов и обрывков, стало 44 — каждая реплика сцены ровно один раз.
- **Вживую после этого (летсплей, сцена с Ёринобу дважды):** «лесенка» и пропадание нижней реплики — чисто; нашлись ещё два случая — голое имя следующей реплики в конце чтения («…Скоро пройдёт. Эвелин:» — красное имя проявляется раньше голубого текста) озвучивалось голосом прежнего говорящего, и при появлении реплики ниже длинной строки «добавившаяся часть», отрезанная по длине, задевала конец прежней строки («ыло!») или новое имя («и: Неплохо»), потому что OCR по-разному расставляет пробелы. Решение: голое имя в конце чтения отрезается до обработки; продолжение, в котором реплики нескольких говорящих, разбирается целиком по репликам со сверкой с предыдущим чтением (выросшая реплика даёт только свою новую часть). Запись 5 минут — без изменений (44 озвучки).
- **Зона «Диалоги» летсплея поднята** с 0,83 до 0,76 экрана (скрипт `captures/set_zone_top.py`, запускает пользователь — запись Claude в `%APPDATA%` уходит в песочницу): «лесенка» из длинной реплики и ещё одной занимает 3–4 строки.

## Этап 8 — удобство (2026-10-05)

**Что скачивается** (`resources/models.toml`, ≈ 100 МБ): детектор `ch_PP-OCRv5_det_mobile.onnx`, распознаватель `eslav_PP-OCRv5_rec_mobile.onnx` (адреса и SHA-256 — из `default_models.yaml` RapidOCR 3.9.2, modelscope.cn) и `v5_cis_base.pt` Silero (models.silero.ai). Silero контрольных сумм не публикует: SHA-256 взят у файла, проверенного на этапе 3, размер совпадает с сервером (91 680 514 байт). `cyrillic` не качается — приложение его не использует, бенчмарк и инструменты берут модели из кеша библиотек, как раньше. `silero-stress` приходит с pip-пакетом, качать нечего.

**Куда и как:** `models/rapidocr/…`, `models/silero/…`; файл пишется как `*.part` и переименовывается только при совпавшем SHA-256 — прерванная загрузка не выглядит моделью. При старте наличие проверяется по размеру (хешировать 100 МБ на каждом запуске — лишняя секунда), хеш — сразу после скачивания. Скачивание — `urllib` из стандартной библиотеки, без новых зависимостей. Движки получают пути (`RapidOcrEngine(det_path, rec_path)` → `Det/Rec.model_path`, при заданном пути RapidOCR ничего не качает; `SileroEngine(model_path)`); без путей — встроенные механизмы библиотек (инструменты).

**Прогресс (выбор пользователя):** окно «Скачиваю модели» с полосой, МБ из МБ и текущим файлом; закрывается само, при ошибке — текст и «Повторить»; «Выход» отменяет загрузку и закрывает приложение (без моделей оно не работает). В CLI `watch`/`run` — строка прогресса в консоли раз в процент.

**Автозапуск:** команда `"<venv>\Scripts\pythonw.exe" -m subvoicer --autostart`; с флагом `--autostart` приложение стартует только в трей, без окна настроек. При каждом старте с включённой галочкой команда в реестре сверяется и переписывается, если изменилась (переезд venv, новые флаги). Лог настраивается первой строкой `main()`, до Qt и проверки второго экземпляра, — ранний выход тоже оставляет след.

## Этап 7 — зоны по хоткею и отладка (2026-10-05)

**Ручное чтение — `sources/manual.py` (`ManualReader`):** одно чтение зоны (`read_once`, строки через перевод строки), фильтр мусора, без стабилизатора и dedup — что попросили, то и читается, даже если уже звучало. Голос и говорящий — по политике зоны через `ProfileRouter.manual`, приоритет `manual`.

**Несколько говорящих в одном ручном чтении** (ТЗ 1.17 разбивает строку по именам): вторая и следующие реплики идут как ручные *продолжения* того же канала — планировщик ставит их в очередь за первой, а не обрывает её. Пауза автоозвучки их не сбрасывает. Ручная реплика другого канала по-прежнему обрывает всё.

**«Выделить и прочитать»:** маска `adaptive` (как у шаблона «Записка» — текст любого цвета), говорящего нет, голос — рассказчик профиля, игра приглушается; OCR и порог уверенности — из профиля. Окно выделения — замёрший кадр ровно поверх изображения игры (`client_rect` с учётом масштаба монитора), Esc или правая кнопка — отмена, щелчок без протяжки — выделить заново. Доступно, только когда есть активная игра.

**Клавиши зон регистрирует фасад** (как общие, решение этапа 6, отдельный `services/hotkey_service.py` не понадобился): по `GameActivated` берутся зоны `hotkey` раскладки текущего соотношения сторон, по `GameClosed` снимаются. Общее действие на той же клавише важнее, зона пропускается с предупреждением в логе. Кадр для чтения — последний кадр идущего захвата, а если зон `auto` нет и захват не запущен — разовый кадр WGC.

**Конфликт клавиш проверяется и при сохранении зон**, а не только при назначении: клавиша, которую дал шаблон, могла совпасть с общей, назначенной позже. Проверяются общие клавиши и зоны этой же раскладки: раскладки разных соотношений сторон не бывают активны одновременно, и «Записке» в 16:9 и 21:9 удобно иметь одну клавишу.

**Кадр Ctrl+Alt+D открывается в редакторе по скриншоту** кнопкой «Открыть в редакторе» в уведомлении «Кадр сохранён»; в режиме разработчика выбор скриншота начинается с папки `captures/`.

## Правки после этапа 5 — ТЗ 1.17 (2026-10-01)

**Имя при запасном входе OCR.** На Cyberpunk имя красное, текст голубой: при уверенности < 0.8 побеждал вход «masked», где имя закрашено, — реплика шла без говорящего и сбивала dedup («Мои человек…» после «Кирк: Мой человек…» читалось как новая). В зоне `prefix` имя из основного входа ставится перед победившим текстом.

**Несколько говорящих в одном субтитре** («Ви: А ты ещё кто? Джеки: Вылезай.») режутся по «Имя:» после конца предложения, только если строка начинается с принятого имени, — чтобы «Слушай: …» в обычной фразе не стало говорящим. В имени теперь не бывает `. ! ? …`.
Отброшено: резать по любому «Слово:» — ложные имена в обычном тексте.

**Мигание субтитра — не новая реплика** (решение пользователя). На летсплее Cyberpunk 3 повтора на ~22 реплики: зона пустела на 108–112 мс, затем тот же текст (сходство 97–98) — по п. 3 ТЗ 4.4 это новая реплика. Паузы между разными субтитрами там тоже 108–220 мс (сходство 24–67), поэтому порог только по длительности не работает; правило — пустота < 300 мс **и** тот же текст. Параметр `flicker_ms` пока только в коде (`StabilizationSettings`), в профиль не вынесен — иначе нужна новая `schema_version`.

**OCR по реальным кадрам** (`tools/real_bench.py`, 7 кропов Cyberpunk 2077 2560×1440 в `tests/fixtures/real/cyberpunk`):

| модель | увеличение | вход raw, CER | masked, CER |
|---|---|---|---|
| cyrillic | ×1 | 10.8% | 46.8% |
| cyrillic | ×1.5 | 10.4% | 35.4% |
| cyrillic | ×2 | 25.1% | 34.4% |
| eslav | ×1 | **5.6%** | 46.6% |
| eslav | ×1.5 | 6.4% | 34.0% |
| eslav | ×2 | 20.7% | 33.3% |

Высота строк на этих кадрах 25–37 px — прежний порог увеличения (< 32 px) срабатывал почти всегда. Синтетика (120 изображений, вход raw): `cyrillic` 0.36% с увеличением / 0.34% без, `eslav` 0.54% / 0.54%. Решение: порог увеличения 20 px, модель по умолчанию `eslav`. Контрактный тест `tests/contracts/test_real_frames.py` держит CER на кадрах Cyberpunk ≤ 8%.
Остаётся: шрифт Cyberpunk — «а» похожа на «о» («нахрено», «сломоть»), так ошибается и `eslav`. Исправлять словарём или языковой моделью — отдельное решение, не сейчас.

## Этап 5 — профили, зоны и персонажи (2026-10-01)

**Имя с ошибкой OCR — по числу отличающихся букв (ТЗ 1.16, решение пользователя).** `ratio >= 90` из ТЗ не ловит одну ошибку в имени короче 10 букв: «Джудн»/«Джуди» — 80, «Панан»/«Панам» — 80, «Такзмура»/«Такэмура» — 87,5. Теперь 4–9 букв — 1 ошибка, от 10 — 2, короче 4 — только точно; из подходящих — ближайший.
Отброшено: порог `ratio` 80 — сливает «Джуди» и «Джуда», а длинные имена с двумя ошибками не ловит; таблица похожих букв OCR — не ловит ошибку в «непохожей» букве.

**Голос персонажу назначается, когда реплика уходит в планировщик**, а не когда начинает звучать: так голос известен до синтеза. Реплика, отброшенная очередью, тоже успевает назначить голос — на результат почти не влияет.

**Импорт персонажей:** имя или вариант из файла, которые и так сопоставляются с персонажем (в т. ч. с ошибкой OCR), в варианты не добавляются; пол из файла у найденного незакреплённого персонажа ставит `gender_locked = true`, как у нового.

**Говорящий `color`:** слова цвета имени (маска, расширенная до слов) закрашиваются чёрным во входе OCR текста, имя читается отдельным OCR по рамке маски имени. Из маски текста пиксели имени исключаются до автомата 4.4.

**Правки профиля применяются сразу.** GameWatcher раз в секунду сверяет время изменения файла активного профиля; при изменении профиль перечитывается, а захват и зоны пересоздаются, только если поменялись зоны раскладки или соотношение сторон. Сохранение персонажей перечитывает файл с диска и применяет изменение к нему — ручная правка во время работы не теряется.

**Переопределение `match_ratio` в зоне не действует**: `Deduplicator` общий на профиль (шаг 0 сравнивает источники между собой). Остальные поля `stabilization` и `ocr` зоны работают.

## Этап 4 — ducking (2026-10-01)

**Порт `Ducker`: `set_gain(pid, gain)` + `restore_all()` вместо `duck/restore`.**
Почему: плавный переход (150 мс) — это много шагов громкости. Время считает чистая огибающая `pipeline/speech/ducking.py` (`DuckEnvelope`, через `Clock`), движок только ставит громкость `gain × исходная`. Порт в ТЗ (раздел 5.3) был черновым; согласовано с пользователем — ТЗ 1.15.
Отброшено: плавность внутри движка в своём потоке — время мимо `Clock`, не тестируется на фейках.

**Приглушение начинается с команды Play, а не с первого звука.** Переход 150 мс идёт одновременно с синтезом первого куска, к началу речи игра уже тихая. Состояние берётся каждый шаг из `scheduler.current` (есть ли сейчас реплика с `duck`), поэтому обрыв и сразу новая реплика не возвращают громкость между ними.

**Возврат громкости — тоже за `duck_fade_ms`, после задержки `duck_release_ms`.** В ТЗ задана только задержка возврата; скорость перехода одинакова в обе стороны, частичный переход короче пропорционально.

**Запись exe, чьи сессии не найдены при восстановлении, остаётся в `ducking_state.json`.** ТЗ: «при старте громкость восстанавливается для всех найденных сессий, после чего файл очищается». Если игра закрыта во время приглушения, Windows запомнит её тихой, а сессии для восстановления нет. Запись остаётся: громкость восстановится, когда сессии найдутся (следующий старт или конец следующей реплики), а новое приглушение считается от сохранённого значения, а не от уже приглушённого.
Отброшено: очищать файл всегда — игра, закрытая во время реплики, навсегда осталась бы на 40%. Согласовано — ТЗ 1.15.

**Не удалось записать файл состояния — не приглушаем.** Без записи на диске падение оставило бы игру тихой.

**Список аудиосессий обновляется раз в секунду.** Перебор сессий pycaw занимает ~20 мс, шаг сервиса — 10 мс; смена громкости по закешированным сессиям — 0,09 мс. Новая сессия игры подхватывается не позже чем через секунду.

**Проверка на настоящем звуке** (процесс с тоном, 2026-10-01): приглушение до 0.4, `taskkill /F` приглушающего процесса, новый запуск — громкость 1.0, файл пуст.

**Режимы наложения реплик `overlap_mode` (решение пользователя, ТЗ 1.14, 4.9).** После игры пользователь попросил не обрывать недочитанную реплику и сделать поведение настраиваемым. Выбраны все четыре режима: `cut` (как было), `queue`, `speedup` (по умолчанию), `adaptive`; скорость — только `--rate` и окно настроек (хоткеи скорости отклонены). Меток времени слов Silero не отдаёт (`return_ts` → «This model doesn't support»), поэтому «ускорить остаток» сделано без растяжения звука: реплика режется на куски (предложения, длинные — по запятым), не зазвучавшие куски пересинтезируются быстрее, звучащий дочитывается как есть. Предохранитель `max_lag_s` = 8 с. Живой прогон `--scenario speech` (реплики по ~3.4 с звука раз в секунду): в очереди всё звучит ×1.5, дождавшаяся реплика ×1.15; ограничение — реплика короче 90 символов — один кусок, и её звучащую часть ускорить нельзя.
Отброшено: собственное растяжение звука (ТЗ запрещает без согласия); прогноз позиции в тексте по доле проигранного звука (без меток времени ошибается на слово).

**Скорость речи — SSML `<prosody rate="N%">` Silero (ТЗ 4.9: «проверить по документации»).** `apply_tts(ssml_text=...)` у `v5_cis_base` поддерживает и слова (`slow`, `fast`…), и проценты; замер длительности: 115% → ×1.15, 130% → ×1.29, 150% → ×1.48. Ударения `+` в SSML сохраняются (звук с `rate="100%"` совпадает с обычным синтезом побайтно). Пауза на многоточии — `<break time="300ms"/>`. Своего растяжения звука нет. SAPI5: `Rate` −10..10, одна единица ≈ ×1.11 (замер +2 → ×1.24, +4 → ×1.54), `rate` переводится логарифмом.

**silero-stress не трогает слова с `+` (ТЗ 4.7 п. 5: «проверить, не предполагать»).** Проверено на 1.5 даже для ударения, которое библиотека поставила бы иначе («м+олоко», «Арасак+и», «Т+акэмура» остаются). Плейсхолдеры поэтому не нужны; в `pipeline/text/stress.py` оставлена страховка: если маркер всё же изменит слово с ручным `+`, текст размечается повторно с такими словами за плейсхолдерами (проверено тестом с «перезаписывающим» фейком).

**Silero: загрузка и производительность.** Файл модели грузится напрямую из папки пакета `silero/model/`, если он есть; первая загрузка идёт через `silero_tts` во временной папке, потому что он кладёт `latest_silero_models.yml` в текущий каталог. `torch.set_num_threads(4)`: короткая фраза 25–30 мс (1 поток — 62 мс, 8–16 — 25 мс). Первый синтез в 20 раз медленнее — `load()` делает прогрев. Голоса — `model.speakers` с префиксом `ru_` (29 шт.), пол и имя — из `resources/voices/silero_v5.toml`.

**SAPI5: формат 48 кГц моно — тип 38** (39 — стерео: сначала вышло «10 с звука на короткую фразу»). COM-объект голоса создаётся в каждом потоке свой (`threading.local` + `CoInitialize`). Единственный русский голос на машине — Microsoft Irina.

**Плеер — один постоянно открытый поток `sounddevice`** (блок 20 мс): реплика начинается без открытия устройства; куски длинной реплики подкладываются, пока она звучит; обрыв — линейное затухание 100 мс. **Планировщик 4.9 — чистый автомат команд** (`pipeline/speech/scheduler.py`), время — аргументом. Уточнения: автоускорение применяется к репликам `high` (счётчик — про обрывы `high` репликами `high`), продолжение звучит со скоростью своей строки; обрыв строки (новой репликой, «пропустить», ручной репликой) выкидывает её продолжения — и стоящие в очереди, и пришедшие позже (до новой реплики этого канала), иначе прозвучал бы оторванный хвост; «пропустить» переходит к следующей в очереди; пауза автоозвучки обрывает текущую автоматическую реплику и очищает очередь, ручные реплики и «повторить» работают и на паузе; «повторить» играет последнюю автоматическую реплику как ручную, звук — из кеша.

**Голос в CLI до профилей (этап 5).** Режимы `speaker` / `narrator` / `fixed`; `speaker` без персонажей — эвристика пола → голос по умолчанию этого пола, иначе рассказчик; голоса по умолчанию — по правилу создания профиля (4.6). Пока пол голосов не размечен, все три роли — первый голос каталога (`ru_aigul`), это ожидаемо.

**Латиница: похожие буквы OCR и одиночные буквы (решение пользователя, ТЗ 1.13, 4.7 п. 4).** OCR иногда читает русские буквы латиницей («Hy, давай», «Tак», «cумка»): такие слова переводятся в кириллицу, иначе транслитерация даст «Хи, давай». **Подготовка текста, уточнения реализации.** Числа: время `чч:мм`, порядковые с окончанием («45-м» → «сорок пятом», падеж и род по окончанию через `num2words(to="ordinal", case=, gender=)`), проценты с согласованием слова «процент», десятичные, числа с ведущим нулём — по цифрам; падеж количественных числительных по контексту не выводится («до 12 километров» → «до двенадцать километров»). Латиница: в таблицу транслитерации добавлены `ce`/`ci`/`cy` → «се»/«си»/«си» («City» → «Сити», а не «Кити»). Многоточие внутри фразы — пауза, а не конец предложения: при разбивке длинного текста режем после «…» только перед заглавной.

**Три попытки до выполнения критериев.**
1. RapidOCR «как есть» (детектор + распознавание по кускам): CER с подложкой 2.8% — цель не достигнута. Разбор ошибок: детектор режет строку на перекрывающиеся куски по словам; буква на стыке читается дважды («г говорил»), а короткий кусок без контекста строки распознаётся латиницей («Ha», «Hac», «OKHO») или не в том регистре.
2. **Склейка строк** (`RapidOcrEngine(merge_rows=True)`): куски детектора одной строки объединяются, распознаватель читает строку целиком. CER с подложкой 0.7%, без подложки 1.2% — цели достигнуты, но среднее время 114 мс (медиана 72): 97 кропов с мелким шрифтом увеличиваются ×2 (ТЗ 4.3), и детектор на 2400×240 работает 220 мс.
3. **Детектор на уменьшенной копии:** картинка больше 1280 px по длинной стороне уменьшается только для детектора, строки для распознавателя вырезаются из полноразмерной (увеличенной) картинки. Среднее время 81 мс. На мелком тексте: без апскейла CER 0.88% / 79 мс, апскейл с детектором на большой картинке 0.58% / 239 мс, апскейл с уменьшенной копией для детектора 0.77% / 96 мс.
Отброшено: отключить апскейл (хуже на мелком тексте, и это отступление от ТЗ); регулировать размер через `Det.limit_side_len` — RapidOCR при `limit_type = max` молча подменяет лимит своим (960 / 1500 / 2000 по размеру картинки), поэтому его ресайз выключен (`limit_type = min`, 32), а масштабирует движок сам.

**Прочие настройки RapidOCR:** классификатор поворота выключен (субтитры не повёрнуты); 4 потока onnxruntime — то же время, что и на всех 16, меньше конкуренции с игрой; 4-канальный вход переводится в BGR самим движком (RapidOCR считает 4 канала RGBA, а кадры захвата — BGRA).

**Варианты входа (б) и (в) проигрывают из-за удаления шума в маске.** Порог ТЗ 4.2.1 (компоненты < 0.02% площади, ~29 px на зоне 1200×120) удаляет точки, запятые, двоеточия и точки над «ё». Для детекции изменений это безвредно, а вход (а) от маски не зависит, поэтому порог не менялся.

**Метрика.** CER считается по распознанному тексту **до** фильтра мусора (отброшенные — отдельной долей), по категории — сумма расстояний / сумма длин. Нормализация — только пробелы (ТЗ 9), поэтому «...» → «…» (так модель читает многоточие) считается 3 ошибками; на озвучку не влияет. «С подложкой, все фоны» включает «неон» — ТЗ говорит «все изображения с подложкой»; без «неона» результат тот же (0.8%).

**Маски (ТЗ 4.2.1), решения реализации.** «Яркость» для `bright_on_dark` / `dark_on_bright` — V из HSV (максимум из B, G, R), чтобы жёлтый и бирюзовый текст тоже считался светлым (по яркости-luma бирюзовый ≈ 174 < 200). Закрытие — ядро 3×3. `adaptive`: `ADAPTIVE_THRESH_MEAN_C`, окно 31, C = 15; полярность выбирается автоматически — текстом считается меньший по площади класс разбиения Оцу (для записок бывает и тёмный текст на светлом, и наоборот). Диапазон `color` в бенчмарке — H ±10, S и V ±80 (решение пользователя, ТЗ 1.9).

**Высота строки для апскейла** оценивается по маске: медиана высот горизонтальных полос, где есть пиксели маски (полосы тоньше 3 px — шум).

**Windows OCR:** уверенности не отдаёт — строки получают 1.0 (`capabilities.returns_confidence = False`), поэтому для него не работают фильтр по уверенности и перебор вариантов. Колёса `winrt` несут свою `msvcp140.dll` 14.29; если она загружена первой, последующий `import onnxruntime` падает с access violation. Перед первым импортом `winrt` движок загружает системную `msvcp140.dll` (14.42) — Windows переиспользует уже загруженную библиотеку. Для работы нужны дополнительные проекции `winrt-Windows.Graphics.Imaging`, `.Globalization`, `.Storage.Streams`, `.Foundation`, `.Foundation.Collections` — части той же зависимости из стека.

**Синтетика.** Цвета текста (RGB): белый 255,255,255; жёлтый 255,216,58; светло-голубой 154,212,255; бирюзовый 63,224,208. По 20 изображений на каждое сочетание фон × подложка (360), остальные параметры случайны. Двухстрочных — 33 из 360: большинство фраз помещается в строку 1120 px.

**`opencv-python` исключён из разрешения зависимостей (`[tool.uv] exclude-dependencies`).**
Почему: `rapidocr` и `windows-capture` объявляют зависимость на полный `opencv-python`, а он ставится в тот же каталог `cv2/`, что и `opencv-python-headless`: какой пакет встал последним, тот и работает, а удаление одного ломает другой. ТЗ требует headless (Qt внутри OpenCV конфликтует с PySide6). Обеим библиотекам нужен только API `cv2`, который headless даёт целиком — smoke-тест OCR проходит.
Отброшено: оставить оба пакета — недетерминированная установка; `override-dependencies` с невыполнимым маркером — обходной приём, `exclude-dependencies` делает то же явно.

**`torch` берётся с PyPI, отдельный индекс PyTorch не подключён.** На Windows колесо `torch` с PyPI — CPU-сборка (`2.14.0+cpu`, `torch.version.cuda = None`). Условие ТЗ «если тянет CUDA — подключить индекс» не сработало. Если на другой платформе (Linux) приедет CUDA-вариант — вернуться к индексу `https://download.pytorch.org/whl/cpu`.

**Контракты `import-linter` (6 шт., `pyproject.toml`).** Слои `ui|cli → app → services → sources → pipeline → config → core`; `engines` импортирует только `core`; сами `engines` импортирует только `app`; `ui`/`cli` не ходят в `services`/`sources`/`pipeline`; Windows-модули (`win32*`, `pywintypes`, `comtypes`, `pycaw`, `winrt`, `windows_capture`, `dxcam`, `winreg`) только в `engines`; `PySide6`/`shiboken6` только в `ui`. Проверено: временные импорты `PySide6` в `pipeline`, `winreg` и `windows_capture` в `services`, `pipeline` из `engines`, `services` из `pipeline` и `cli` — ловятся, после отката всё зелёное.
Отложено: контракт «`engines/hook/host.py` импортирует только `core`» — появится на этапе 11 вместе с модулем (import-linter не принимает контракт на несуществующий модуль).

## Решения этапа планирования (2026-09-28)

Приняты при обсуждении, до начала реализации. Подробности — в ТЗ.

**OCR — RapidOCR + PP-OCRv5 cyrillic mobile, CPU.**
Почему: точнее Tesseract и EasyOCR на игровых шрифтах, ставится без PaddlePaddle и torch, отдельная модель кириллицы весит несколько МБ.
Отброшено: PP-OCRv6 — единая модель без кириллицы; Tesseract — слаб на стилизованных шрифтах; WinRT OCR — оставлен запасным (быстрый, но менее точный).

**TTS — Silero v5 (`v5_cis_base`) + `silero-stress`, CPU.**
Почему: лучшие открытые русские голоса с ударениями и омографами, очень быстрый синтез на CPU, 29 голосов, лицензия MIT у этой связки.
Отброшено: `v5_ru` — некоммерческая лицензия; F5-TTS и XTTS — проблемы с ударениями и нужен GPU; Qwen3-TTS — хорош, но на GPU, который занят игрой (оставлен поздним этапом 10).

**Захват — windows-capture (Windows Graphics Capture) окна, fallback DXGI.**
Почему: захват именно окна не зависит от монитора и перекрывающих окон; кадр приходит только при изменении.
Отброшено: mss — медленно; DXcam/BetterCam как основной — захватывают монитор, не окно.

**Всё тяжёлое — на CPU.** Видеокарта занята игрой; Ryzen 7 5800X справляется с OCR и Silero.

**Нет модуля перевода.** Целевые игры имеют русские субтитры.

**Детекция изменений по маске текста, а не по пикселям.** Фон в катсценах двигается постоянно; сравнение пикселей давало бы OCR на каждом кадре.

**Новая реплика обрывает старую, исчезнувшая с экрана — дочитывается, продолжение встаёт в очередь.** Так ближе к живой озвучке и не копится отставание.

**Универсальные зоны с поведением (авто / по клавише / выкл) и приоритетами** вместо жёстких типов «диалог / записка».

**Словарь произношений со звёздочкой** (`Арасак* → Арас+ак*`) — иначе в русском словарь не покрывает падежи.

**Хуки к движку — поздний этап 11, в отдельном процессе, с проверкой античита.** Права администратора только у вспомогательного процесса; падение хука не роняет приложение.

**Архитектура — чистое ядро (`pipeline/`) и оболочка (`services/`, `engines/`) с правилами импорта, проверяемыми `import-linter`.** Почему: автоматически ловит нарушения слоёв при AI-разработке; алгоритмы тестируются без Windows и игры.

**Интерфейс — PySide6, стандартный тёмный заголовок окна Windows, свои уведомления у трея.** Свой заголовок окна в Qt — источник багов; стандартные уведомления Windows не поддерживают кнопки из Qt.

**Python 3.12.** Самая безопасная версия для torch, onnxruntime и остального стека; `windows-capture` поставляется abi3-колесом и работает на любой версии от 3.9.
